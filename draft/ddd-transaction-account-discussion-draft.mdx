# Account와 Transaction 분석 패턴을 통한 도메인 무결성 설계

> **요약**: 마틴 파울러의 Analysis Patterns 중 Account와 Transaction 패턴을 비교할 때 발생하는 Entry 객체의 모순을 해소하고, 복식부기 모델에서 Transaction을 독립된 Aggregate Root로 다루며 데이터베이스 외래키 매핑까지 어떻게 풀어낼 수 있는지에 대한 설계적 결론을 제시한다.

## 플롯 후보

### Plot A: 개념 정립형 (Concept Definition)
- **적합한 독자/상황**: DDD 입문자 혹은 회계/결제 시스템 기초 설계자.
- **구성 흐름**: 
  1. 문제 제기: 두 패턴 설명에서 나타난 Entry의 불일치
  2. 원인 분석: 각 패턴이 초점을 맞춘 관점의 차이
  3. 모순 해소: Association Object로서의 Entry
  4. 결론: 올바른 개념 통합
- **이 플롯의 강점**: 파편화된 지식을 하나로 통합하며 명확한 개념 모델을 제공한다.
- **주의할 점**: 지나치게 이론적인 설명으로 빠져 구현 코드 예시가 부족해지지 않도록 주의.

### Plot B: 의사결정 가이드형 (Decision Guide)
- **적합한 독자/상황**: 실제 결제/정산 도메인을 설계 중인 개발자.
- **구성 흐름**: 
  1. 요구사항: 회계 장부 무결성 보장을 위한 모델 설계
  2. 딜레마: Transaction과 Account 중 누가 주도권을 가지며, Aggregate Root는 어떻게 나눠야 하는가?
  3. 의사결정: Transaction을 독립된 AR로 도출하고, Account와 분리.
  4. 구현 및 DB 매핑: Eventual Consistency와 외래키 구조.
- **이 플롯의 강점**: 실무에서 바로 써먹을 수 있는 구체적인 설계 가이드와 DB 스키마 팁을 제공한다.
- **주의할 점**: 개념 자체를 모르는 독자를 위해 초반에 Double-Entry(복식부기)의 필수성을 짧게 짚고 넘어가야 한다.

### Plot C: 진화 과정형 (Evolutionary)
- **적합한 독자/상황**: 시스템이 복잡해지면서 기존의 단순한 잔액(balance) 컬럼 모델의 한계를 겪어본 개발자.
- **구성 흐름**: 
  1. 초기 모델: 단순 잔액 업데이트 모델의 문제점
  2. 1차 진화: Account 패턴 도입 (Entry 기록 추가)
  3. 2차 진화: 복식부기와 Transaction 패턴 도입의 필요성
  4. DDD 관점의 최종 설계: 도메인 서비스가 두 AR(Transaction, Account)을 조율하는 구조.
- **이 플롯의 강점**: 문제 상황에 공감하며 자연스럽게 패턴의 필요성을 설득할 수 있다.
- **주의할 점**: 초반부(단순 잔액 모델)가 너무 길어지면 핵심(Transaction AR) 논의가 묻힐 수 있다.

## 주의사항 / 잊지 말아야 할 점

- Transaction과 Account를 하나의 Aggregate Root로 묶는 실수를 경계한다는 점을 명시할 것.
- Entry는 Transaction에 의해 생성되고 Account로 전달되는 불변 객체(Value Object)라는 점을 강조할 것.
- Eventual Consistency(최종 일관성) 혹은 Outbox Pattern 도입이 필요한 도메인 복잡성을 다뤄줄 것.
- DB 매핑 시 Entry가 Transaction과 Account의 외래키를 갖는다는 실무적 구조를 포함할 것.

export const TreeNode = ({ node }) => {
  const isUser = node.source === 'USER' || node.source === 'USER_EXPLICIT';
  const isModel = node.source === 'MODEL';
  const nodeClass = `tree-node ${isUser ? 'tree-node-user' : isModel ? 'tree-node-model' : 'tree-node-system'}`;
  
  return (
    <li>
      <a href={`#${node.id}`} className={nodeClass}>
        <strong>{node.source}</strong><br/>
        <span style={{color: '#888', fontSize: '11px'}}>{node.type}</span><br/>
        <span style={{color: '#bbb', fontSize: '10px'}}>Step {node.step_index}</span>
      </a>
      {node.children && node.children.length > 0 && (
        <ul>
          {node.children.map(child => <TreeNode key={child.id} node={child} />)}
        </ul>
      )}
    </li>
  );
};

export const ConversationTree = ({ roots }) => {
  return (
    <div className="tree-container">
      <div className="tree">
        <ul>
          {roots.map(root => <TreeNode key={root.id} node={root} />)}
        </ul>
      </div>
    </div>
  );
};

export const ConversationDetails = ({ nodes }) => {
