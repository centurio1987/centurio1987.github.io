# Post Draft 스킬

`raws/`에 적어둔 아이디어/단서 메모를 읽어, **3가지 플롯 후보**와 **해당 주제에서 잊지 말아야 할 주의사항**을 담은 스캐폴드 파일을 `draft/`에 `<원본파일명>-draft.md` 이름으로 생성한다.

본문 초안 작성은 이 스킬의 범위가 아니다 — 사용자가 플롯을 고른 뒤 별도로 진행한다.

## 워크플로우 상의 위치

```
raws/<메모>.md      (사용자가 작성)
  → [post-draft]    draft/<메모>-draft.md   (플롯 3개 + 주의사항)
  → 사용자가 플롯 선택 + 본문 작성
  → review-post → post-finalize → publish-post → src/content/posts/
```

## 동작 순서

### 1. 아이디어 파일 경로 확인

인자로 파일 경로가 전달된 경우 그대로 사용한다. 그렇지 않으면 `raws/` 하위를 살펴 후보를 제시하거나 사용자에게 묻는다:

> "어느 아이디어 파일을 기반으로 draft를 만들까요? (예: `raws/IDEAS.md`)"

경로에 공백/한글이 포함될 수 있으므로 따옴표 처리/이스케이프에 유의한다.

### 2. 아이디어 파일 읽기 및 분석

`Read` 도구로 **파일 전체**를 읽는다. 들여쓰기 bullet형, heading+산문형 등 형식이 다양하므로 끝까지 읽어 다음을 식별한다:

- 글의 추정 주제 (한 줄)
- 한 문장 요약 — 이 글이 결국 무엇을 말하려 하는지
- 핵심 주장 / 하위 논점들
- 사용자가 이미 결론을 내려둔 부분과, 아직 열려 있는 분기점

`raws/IDEAS.md` 처럼 여러 주제가 섞인 메모라면, 어느 항목(주제)을 글감으로 삼을지 먼저 사용자에게 확인한다.

아이디어가 너무 빈약하면(의미 있는 본문이 5줄 미만) 그 사실을 알리고 보강 여부를 묻는다.

### 3. 출력 경로 결정

`draft/<원본 stem>-draft.md`를 만든다. (입력이 `raws/`가 아니어도 출력은 항상 `draft/`)

예: `raws/애그리거트.md` → `draft/애그리거트-draft.md`

이미 존재하면 덮어쓰기 전에 사용자에게 확인한다. 필요 시 `draft/` 디렉터리를 생성한다.

### 4. 스캐폴드 생성

`assets/DRAFT_TEMPLATE.md`를 읽어 구조를 베이스로 삼고, 아래 항목들을 채워 `Write`로 저장한다.

**채워야 할 항목:**

- frontmatter `source`: 입력 아이디어 파일 경로 (레포 루트 기준 상대경로)
- frontmatter `generated`: 오늘 날짜 (`YYYY-MM-DD`)
- frontmatter `category`: 아래 카테고리 슬러그 중 추정값 (확신이 없으면 비워두고 주석으로 후보 제시)
- `# [추정 주제 한 줄]` / `> [한 문장 요약]`
- **Plot A / B / C**: 각 플롯은 서로 *명확히 다른* 서사 구조를 갖도록 한다. 유형 예시(이 중에서 고르되 더 적합한 형태가 있으면 그것을):
  개념 정립형 / 사례 분석형 / 의사결정 가이드형 / 반례 중심형 / 진화 과정형 / Q&A형 / 비교 분석형.
  각 플롯마다: `적합한 독자/상황`, `구성 흐름`(3~6단계), `이 플롯의 강점`, `주의할 점`.
- **주의사항 / 잊지 말아야 할 점**: 이 *특정 주제*에 한정된 항목만 4~8개. 보편 글쓰기 팁("결론을 먼저 써라" 등)은 적지 않는다.
- **선택한 플롯** 섹션은 비워둔다(템플릿 주석만 남긴다).

### 5. 완료 안내

생성된 경로를 알린 뒤 다음 단계를 짧게 안내한다:

> "`draft/<…>-draft.md` 에 스캐폴드를 만들었습니다.
> 마음에 드는 플롯을 `## 선택한 플롯`에 적고 본문을 채우신 뒤, `review-post`로 검토하세요."

## 카테고리 슬러그 (frontmatter `category` 값)

`planning`(기획) · `architecture`(아키텍처) · `strategy`(전략) · `skills`(기술) · `design`(설계) · `research`(리서치) · `quality`(품질) · `leadership`(리더십)

이 슬러그는 `src/content.config.ts`의 enum 및 `src/lib/categories.ts`와 일치해야 한다.

## 분석 시 지킬 원칙

- **3개 플롯은 겹치지 않게.** 서사 구조 자체가 달라야 한다.
- **주의사항은 토픽 특화로.** 입력에서 실제 언급됐거나 자연스럽게 따라오는 항목만.
- **한국어로 작성.** 기술 용어는 원어 그대로(DDD, Aggregate, Composition 등).
- **아이디어 파일을 끝까지 읽는다.**
- **사용자가 이미 내린 결론은 존중한다.**
- **밈 마커 보존.** 입력·초안에 `<<meme: ...>>`(인터넷 밈·움짤 자리표시자)가 있으면 그대로 남긴다. 여기서 채우지 않는다 — 채우려면 `meme-inserter` 스킬을 쓰고, 발행 단계(post-finalize)가 자동 위탁한다.

- `raws/IDEAS.md` — 들여쓰기 bullet형, 여러 주제 혼재 메모

두 형태(bullet형 / heading+산문형) 모두 동일하게 처리한다.
