# 섹션 패턴 메뉴 (다관점 체크리스트)

ORDER가 요구한 "여러 관점"을 섹션 유형으로 환원한 것. 아웃라인 단계에서 각 유형을 **칸**으로 두고
이 주제에 맞게 채우거나(필수), 맞지 않으면 비우되 **왜 뺐는지 메모**한다(조건부). 억지로 다 채우지 말 것.

## 분류

- **필수**: 정의 · 핵심 원리 · 실무 시나리오 · 오해 포인트 · 마무리/요약
- **조건부**: 관련 장비 · 관련 프로토콜/기술 · 다이어그램 · React 시뮬레이션 · 실습 과제 · 구현/코드 · 함정·안티패턴↔베스트프랙티스 결과 비교

---

## 1. 엄밀한 정의 (필수)
- **목적**: 용어를 흐릿하게 쓰지 않게 한다. 이후 모든 설명의 기준점.
- **필수 요소**: 느슨한 통념 정의 → 그게 왜 부족한지 → 엄밀한 정의 → 인접 개념과의 경계.
- **좋은 예**: "라우터를 '인터넷 연결 장치'라 부르지만, 정확히는 *서로 다른 네트워크 사이에서 L3 패킷을 포워딩*하는 장비다. 스위치(L2)와의 차이는 …"
- **나쁜 예**: "라우터는 네트워크 장비다." (경계 없음, 깊이 없음)

## 2. 핵심 원리 — 메커니즘 (필수)
- **목적**: "무엇"이 아니라 "어떻게/왜"를 이해시킨다. 해부학적 깊이가 여기서 나온다.
- **필수 요소**: 직관적 비유 → 실제 동작(단계/상태 변화) → 왜 그렇게 설계됐는지(트레이드오프).
- **좋은 예**: 비유로 그림을 잡고, 곧바로 실제 동작으로 내려가 비유의 한계까지 짚는다.
- **나쁜 예**: 비유만 하고 실제 동작은 건너뛴다 / 동작은 나열하나 "왜"가 없다.

## 3. 관련 장비 (조건부)
- **목적**: 주제에 물리/논리 장비가 관여할 때, 각 장비의 정체와 한계를 또렷이.
- **필수 요소**: 장비명 · 역할 · 동작 계층/원리 · 한계·오용 사례. 표로 정리하면 스캔성↑.
- **뺄 때**: 장비 개념이 없는 순수 소프트웨어 주제 → "이 주제는 장비가 관여하지 않아 생략" 메모.

## 4. 관련 프로토콜·기술 (조건부)
- **목적**: 표준/프로토콜/기술을 "문제→해결"로 이해시킨다.
- **필수 요소**: 각 프로토콜이 *어떤 문제를 풀려고 등장했는지* → 핵심 동작/필드 → 버전/표준 근거(RFC 등).
- **좋은 예**: "ARP는 'IP는 아는데 MAC을 모른다'는 문제를 푼다. 브로드캐스트로 묻고 …(RFC 826)"
- **나쁜 예**: 필드 표만 덤프하고 왜 쓰는지 없음.

## 5. 실무 시나리오 워크스루 (필수, ORDER 핵심)
- **목적**: 현실에서 어떻게 굴러가고 어디서 터지는지. 글의 설득력·실용성의 핵심.
- **필수 요소**: 시나리오를 **단계별**로 쪼개고 각 단계마다 → ① 원리/동작 ② 흔한 문제 ③ 진단·해결 ④ 팁/노하우.
  가능하면 실제 명령/로그/설정/코드.
- **좋은 예**: "패킷이 안 나간다" 시나리오를 핸드셰이크 단계별로 따라가며 단계마다 의심 지점과 `tcpdump` 확인법을 붙인다.
- **나쁜 예**: "문제가 생기면 설정을 확인하세요" 수준의 두루뭉술.

## 6. 오해하기 쉬운 포인트 (필수)
- **목적**: 입문자·경력자 모두 빠지는 함정을 미리 제거.
- **필수 요소**: 흔한 오해 → 왜 틀렸는지(반례/원리) → 올바른 이해.
- **좋은 예**: "MTU와 MSS를 같게 알지만 …(헤더만큼 차이)."

## 7. 다이어그램 (조건부)
- **목적**: 글로 길게 설명할 구조/흐름을 한눈에.
- **두 갈래**(마커 비충돌):
  - **구조형 시각물**(다이어그램·차트·인포그래픽·hero): ```` ```viz``` ```` 명세 블록으로 남겨 `make-image`(viz 엔진, bbangto-ui-visualization)가 코드로 구현. ChatGPT 이미지 생성 안 씀. kind: ProcessSteps/Comparison/Flowchart/Statistics/PosterEditorial.
  - **인터랙티브 시뮬**(움직여야 이해되는 것): 시뮬 명세를 남겨 `react-sim`이 co-located `.tsx`로 구현. `client:visible`.
- **뺄 때**: 구조가 단순해 산문으로 충분하면 생략.

## 8. React 시뮬레이션 (조건부, ORDER 명시)
- **목적**: "조작하며 관찰"해야 이해되는 동적 개념(상태 변화·단계 진행·파라미터 영향)을 체험시킨다.
- **필수 요소**: co-located `.tsx`로 작성 + `client:visible` + 본문에 "무엇을 조작하고 무엇을 관찰하라" 안내.
  집필은 시뮬 명세만 남기고 `react-sim`(react-sim-builder)에 위탁한다. 규약·예시는 `react-sim`의 `REACT_SIM_GUIDE.md`.
- **좋은 예**: 창 크기 슬라이더로 TCP 흐름제어가 어떻게 변하는지 즉시 보이기.
- **뺄 때**: 정적 그림으로 충분한 개념 → "동적 요소가 없어 시뮬레이션 생략" 메모.

## 9. 실습 과제 (조건부, 권장)
- **목적**: 손으로 확인해 지식을 체화.
- **필수 요소**: 목표 → 준비물/환경 → 수행 절차(번호) → 기대 결과 → 관찰 포인트(→ 가능하면 검증법).
- **나쁜 예**: 절차만 있고 "무엇을 보면 성공인지" 없음.

## 10. 구현/코드 (조건부)
- **목적**: 원리를 코드로 못박는다.
- **필수 요소**: 최소 실행 가능한 예 → 줄별/블록별 의미 → 흔한 실수.
- **주의**: 코드/다이어그램이 **문맥 없이 먼저** 나오지 않게(먼저 왜 보는지 설명).

## 11. 함정·안티패턴 ↔ 베스트 프랙티스 + 결과 비교 (조건부, 구현/실무 한정)
- **목적**: 잘못된 접근이 *실제로 어떤 결과*를 낳는지 보여, 권장 방식의 당위를 결과로 체득시킨다.
- **§6·§10과의 구분(겹침 금지)**: §6 오해 포인트는 *머릿속 개념 오해*, §10 구현/코드는 *정상 코드 한 벌*. 여기는 **구현 레벨의 함정을 ❌안티패턴 ↔ ✅베스트프랙티스로 나란히 두고 결과 차이를 분석**하는 자리다.
- **필수 요소**:
  ① 함정/안티패턴 명시(왜 빠지기 쉬운지) →
  ② (구현 주제) ❌코드 ↔ ✅코드 나란히 — **의사코드인지 실행 가능 코드인지 명시**, 실행 가능이면 입력·출력·실패 조건을 함께 →
  ③ **결과 비교**(근거 3단계 중 적합한 수준: ⓐ성능이 핵심이면 벤치마크 수치 / ⓑ동작·버그면 로그·실패 재현으로 충분 / ⓒ수치화 부적절하면 정성 비교 + "왜 그런 결과인지" 원리) →
  ④ "그래서 무엇을 택하나" 판단 근거(상황별 선택 기준).
- **비교 표기**: 결과 비교표는 **기본 마크다운 표**로 충분하다. 복잡하거나 대표 이미지급일 때만 `make-image`의 `Comparison` ```` ```viz``` ```` 위탁(단순 비교를 시각물로 흐르게 하지 말 것).
- **좋은 예**: "N+1 쿼리"를 ❌반복 조회 코드 ↔ ✅eager-load 코드로 나란히 두고, **쿼리 수·응답시간(ⓐ)**으로 비교한 뒤 "언제 어떤 걸 쓰나"를 판단 근거로 단다.
- **나쁜 예/뺄 때**: 코드·구현이 없는 개념 주제(예: 네트워크 계층 개론)는 빈칸 + "이 주제는 구현 함정이 없어 생략" 메모. "✅가 더 좋다"만 쓰고 ③ 결과 근거가 없으면 미흡. **억지로 숫자를 지어내지 말 것**(근거 3단계 중 정직한 수준을 고른다).

## 12. 마무리/요약 (필수)
- **목적**: 핵심을 다시 압축, 더 파고들 거리 제시.
- **필수 요소**: 한 문장 핵심 재진술 + 3~5개 take-away + 다음 학습 포인트.

## 깊이 자가 점검 (집필 후)
- 각 핵심 주장에 "왜"가 붙어 있는가? (표면 설명만이면 부족)
- 비전문가가 1절부터 따라오면 막히는 지점이 없는가? (약어·전제 누락 점검)
- 실무 시나리오가 단계별 + 문제/해결/팁을 갖췄는가?
- 한 개념을 최소 2개 관점(예: 정의+시뮬, 원리+시나리오)으로 비췄는가?
- 건조한 스펙 나열로 빠진 절은 없는가? (있으면 "왜 중요한가"를 앞에 붙인다)
- (구현/실무 주제 한정) 안티패턴↔베스트프랙티스를 **결과 차이(재현 가능 근거)**로 비교했는가? "더 좋다"는 주장만 남지 않았는가?
