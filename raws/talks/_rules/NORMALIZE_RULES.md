# 대화 원본 정규화 규칙

> KAN-066-KK9Q50 `S1` 산출물. **무엇을 버리고 무엇을 남기는가**를 고정한다.
> 배치3(`S6`)에서 `.claude/skills/talk-ingest/assets/NORMALIZE_RULES.md` 로 옮긴다.
>
> 여기 적힌 수치는 전부 **표본에서 잰 값**이다. 표본은
> `raws/ddd-transaction-account-discussion.mdx` 하나뿐이므로, 다른 형식이 들어오면
> 어댑터를 새로 쓰되 이 문서의 **하드 실패 조건은 형식과 무관하게 그대로 적용한다.**

## 0. 이 문서가 서는 자리

```text
L1 원문 ──[ 이 문서의 규칙 ]──> 발화 목록 ──[ 교정 ]──> L2 정형본
   불변                          중간 산출물                정본
```

정규화는 **버리기만 한다.** 문장을 고치거나 합치거나 순서를 바꾸지 않는다 —
그건 다음 단계(교정)의 몫이다. 이 단계에서 손을 대면 원문과 정형본 사이에
설명할 수 없는 차이가 생긴다.

## 1. 어댑터 — 어떤 형식인지 먼저 고른다

| 어댑터 id | 인식 조건 | 상태 |
| --- | --- | --- |
| `antigravity-graph-mdx` | `.mdx` 안에 `export const flatNodesData = [` 로 시작하는 줄이 있다 | 구현 대상 |
| 그 외 | — | **실패**. 추측해서 읽지 않는다 |

`conversation-graph-mdx` 스킬(`~/.claude/skills/conversation-graph-mdx/`)이 만든 형식이다.
같은 파일에 `graphData` 와 `flatNodesData` 두 벌이 들어 있는데 **`flatNodesData` 를 읽는다** —
표본에서 `graphData` 는 7 노드(6,058 B)뿐이고 `flatNodesData` 는 51 노드(89,298 B)로,
트리 쪽이 불완전하다.

노드 스키마는 여섯 필드다: `id` · `step_index` · `source` · `type` · `content` · `tool_calls`.

## 2. 남길 것과 버릴 것

**남긴다 — 두 종류뿐이다.**

| `source` | `type` | 조건 | 대담에서의 역할 |
| --- | --- | --- | --- |
| `USER_EXPLICIT` | `USER_INPUT` | — | 질문 |
| `MODEL` | `PLANNER_RESPONSE` | `content` 가 비어 있지 않다 | 답변 |

**버린다 — 나머지 전부.**

| 무엇 | 왜 |
| --- | --- |
| `SYSTEM/*` 전부 (`CONVERSATION_HISTORY` · `EPHEMERAL_MESSAGE` · `ERROR_MESSAGE` · `SYSTEM_MESSAGE`) | 시스템 프롬프트·리마인더·태스크 로그. 대화가 아니다 |
| `MODEL/PLANNER_RESPONSE` 중 `content` 가 빈 것 | 도구를 부르기만 한 껍데기 |
| `MODEL/RUN_COMMAND` · `LIST_DIRECTORY` · `VIEW_FILE` · `GENERIC` | 도구 실행 결과 |
| 모든 노드의 `tool_calls` 배열 | 위와 같은 이유 |

도구 실행 결과를 남기지 않는 이유는 **대담이 두 사람이 나눈 말이지 에이전트의 작업
로그가 아니기 때문**이다. 근거로 인용할 것이 있으면 교정 단계에서 사람이 답변 본문에
직접 넣는다 — 자동으로 끌고 오면 대담에 명령줄 출력이 섞인다.

## 3. 껍데기를 벗기되, 벗기기 전에 메타를 건진다

`USER_INPUT` 의 `content` 는 XML 꼴 래퍼로 싸여 있다.

```text
<USER_REQUEST> … 실제 질문 … </USER_REQUEST>
<ADDITIONAL_METADATA>The current local time is: 2026-06-10T16:27:10+09:00.</ADDITIONAL_METADATA>
<USER_SETTINGS_CHANGE>… Model Selection … Gemini 3.1 Pro (High) …</USER_SETTINGS_CHANGE>
```

- `<USER_REQUEST>` **안쪽만** 질문으로 남긴다.
- `<ADDITIONAL_METADATA>` 는 버리되, **첫 노드의 시각**을 `source.json` 의 `capturedAt`
  후보로 뽑아 둔다.
- `<USER_SETTINGS_CHANGE>` 는 버리되, `Model Selection` 값을 `source.json` 의 `model`
  후보로 뽑아 둔다.

버리기 전에 건지는 이유는 단순하다 — 이 둘 말고는 원본에 출처를 적어 둘 자리가 없다.

## 4. 하드 실패 조건 — 조용히 잘못 읽느니 멈춘다

아래 넷 중 하나라도 걸리면 **비0으로 끝내고 사람에게 넘긴다.** 우회 플래그를 두지 않는다.

1. **`<truncated N bytes>` 가 남길 노드 안에 하나라도 있다.** (§5 참고)
2. 어댑터를 고르지 못했다 — 알 수 없는 형식.
3. 남는 발화가 0개다.
4. §7 의 민감 패턴이 남길 노드 안에서 발견됐다.

질문과 답변이 교대로 오지 않는 것은 **경고**로만 남긴다. 사람이 연달아 두 번 물을 수도
있고, 그건 대담에서 자연스러운 일이다.

## 5. `<truncated N bytes>` — 표본에서 찾아낸 함정

원본 export 는 긴 `content` 의 **가운데를 잘라 내고** 그 자리에 `<truncated N bytes>` 를
끼워 넣는다. 잘린 노드도 문장 끝에서 깔끔하게 끝나기 때문에 **눈으로는 안 보인다.**

표본 실측:

| step | type | 남은 바이트 | 잘린 바이트 |
| --- | --- | ---: | ---: |
| 16 | `VIEW_FILE` | 4,119 | 6,995 |
| 17 | `VIEW_FILE` | 4,119 | 6,932 |
| 19 | `PLANNER_RESPONSE` | 4,120 | 1,367 |
| 22 | `PLANNER_RESPONSE` | 4,116 | 1,857 |
| 25 | `PLANNER_RESPONSE` | 4,119 | 772 |
| 28 | `PLANNER_RESPONSE` | 4,117 | 848 |
| 31 | `PLANNER_RESPONSE` | 4,120 | 2,683 |

**남길 답변 5개가 전부 잘려 있다.** 유실 7,527 바이트 — 답변 실제 분량 28,119 바이트의
**26.8%** 다. 질문 6개는 하나도 안 잘렸다(전부 4,120 바이트 미만).

단서는 바이트 수였다. 답변 5개가 4,116 ~ 4,120 바이트에 몰려 있는데 글자 수는
2,205 ~ 2,709 자로 제각각이다 — 글자가 아니라 **바이트로 자르고 있다**는 뜻이고,
그 상한이 4,120 근처다.

그래서 규칙은 하나다. **잘린 원본은 정본이 될 수 없다.** 다시 받아야 한다.
잘린 채로 봉인하면 "원문을 보존해 뒀으니 언제든 다시 만든다"는 이 카드의 전제가
첫 회부터 거짓이 된다.

## 7. 민감 패턴 필터 — 이 저장소는 공개다

`raws/` 는 커밋되고 저장소는 공개다. 남길 노드에서 아래가 발견되면 §4 의 4번으로
**실패시키고 사람에게 보고한다. 자동으로 치환하지 않는다** — 조용히 바꾸면 L1 이
원문이 아니게 되고, 그러면 이 카드의 3계층이 무너진다.

| 패턴 | 정규식 |
| --- | --- |
| 홈 절대경로 | `/Users/[A-Za-z0-9._-]+` |
| file URL | `file:///` |
| 도구 설정 경로 | `~?/\.(claude\|gemini\|agents)\b` |
| 세션·태스크 UUID | `\b[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\b` |
| 토큰꼴 | `\b(ghp_\|gho_\|sk-\|AKIA)[A-Za-z0-9]{8,}` |
| 이메일 | `\b[\w.+-]+@[\w-]+\.[\w.]+\b` |
| 개인키 헤더 | `-----BEGIN [A-Z ]*PRIVATE KEY-----` |

표본에서 실제로 돌려 본 결과:

| | 홈경로 | fileURL | 설정경로 | UUID | 토큰 | 이메일 | 개인키 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 남길 노드 11개 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 버릴 노드 40개 | 9 | 5 | 8 | 7 | 0 | 0 | 0 |

**§2 의 버리기 규칙이 이미 29건을 전부 걷어낸다.** 필터는 그 규칙이 놓친 것을 잡는
두 번째 그물이지, 첫 번째 방어선이 아니다.

## 8. 중간 산출물의 모양

정규화가 내놓는 것은 **발화 목록**이다. 이것을 파일로 남기지 않는다 — L2 로 가는 길에
잠깐 존재할 뿐이고, 파일로 남기면 정본이 둘이 된다.

```text
[
  { role: "interviewer", index: 0,  text: "…" },   # step_index 를 그대로 보존
  { role: "interviewee", index: 19, text: "…" },
  …
]
```

`index` 를 원본의 `step_index` 그대로 두는 이유는 **L2 에서 원본의 어느 지점인지
되짚을 수 있게 하기 위해서**다. 1부터 다시 매기면 그 연결이 끊어진다.
