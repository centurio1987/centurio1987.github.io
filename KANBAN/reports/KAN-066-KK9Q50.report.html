전략

입력의 실물을 먼저 봤다. raws/ddd-transaction-account-discussion.mdx 가 유일한 대화 원본 표본이고 93KB 다. 그 안은 중첩 JSON 그래프({id, step_index, source, type, content, tool_calls, children})이며 source 는 USER_EXPLICIT · MODEL · SYSTEM, type 은 USER_INPUT · CONVERSATION_HISTORY · EPHEMERAL_MESSAGE 등으로 갈린다. 사람의 발화보다 시스템 프롬프트 · 도구 호출 · 플래너 잡음이 훨씬 많다. 이 상태로는 <QA n q> 골격에 못 넣고, 매번 집필자 컨텍스트에 93KB 를 통째로 올려야 한다.

목적지도 이미 정해져 있다. .claude/authoring/specs/polssin-daedam/spec.json 의 sections 가 frontmatter · qa(repeat) · pullquote 셋이고, 원칙 SP1(n 은 1부터 연속) · SP4(PullQuote 는 요약이 아닌 도달점, 1~2개) · SP5(template: talk · series · order) · SP6(author 는 인터뷰어)은 전부 기계가 검사할 수 있는 계약이다. 즉 발행물은 사람이 손으로 쓸 것이 아니라 구워야 할 것이다.

3계층으로 나눈다

카드가 요구한 "원문/교정본 2계층"에 발행물 1계층을 더해 3계층으로 간다. 2계층으로 끝내면 교정본이 곧 발행물이 되어, 발행물에 손을 대는 순간 "다시 굽기"가 깨지기 때문이다.

| 층 | 무엇 | 어디 | 누가 고치나 | |---|---|---|---| | L1 원문 | 받은 그대로. 불변 | raws/talks/<slug>/source.<ext> + source.json | 아무도 | | L2 정형본 | 노이즈 제거 + 교정된 정본 | raws/talks/<slug>/talk.md | 사람 · AI | | L3 발행물 | 파생. 손대지 않는다 | src/content/posts/talk-<slug>.mdx | 빌더만 |

L1→L2 는 판단이 드는 일(무엇이 질문이고 무엇이 잡음인가, 톤앤매너·비문·맞춤법)이라 스킬이 맡는다. L2→L3 는 계약 검사와 치환뿐이라 스크립트가 맡는다. "스킬로 만들지 스크립트로 만들지"는 양자택일이 아니라 이 경계선의 문제였다.

굳힌 판단 넷

  1. L2 는 markdown 이다 (JSON·YAML 아님). 대담 정본은 사람이 계속 손볼 물건인데 긴 한국어 답변을 JSON 이스케이프나 YAML 블록 스칼라에 가두면 편집이 무너진다. 대신 형식이 흐물해지지 않도록 Zod 파서로 계약을 잡는다 — src/lib/viz/schema.ts 가 ``viz`` 블록에 쓴 것과 같은 방식이다.
  2. 저장 위치는 raws/talks/<slug>/ 다. raws/README.md 가 raws 를 "사용자가 직접 작성하는 공간"으로 정의하고 raws/_proceeded/ 로 봉인하는 관례가 이미 있다. 별도 루트 디렉터리를 새로 파면 유저 입력의 입구가 둘이 된다.
  3. init-post --talk 와 합치지 않는다. 그쪽은 원본 없이 바로 쓰는 빈 스켈레톤 경로이고 이쪽은 내용이 찬 것을 굽는 경로다. 진입점이 다르므로 둘 다 남기고, src/templates/talk-episode.mdx 를 두 경로의 단일 소스로 공유한다.
  4. L3 는 사람이 안 고친다. 고치고 싶으면 L2 를 고쳐 다시 굽는다. 이 규약이 없으면 카드가 요구한 "개선 방향이 바뀔 때 다시 굽는다"가 첫 수정에서 죽는다.

버린 대안 셋

  • 원본을 raws 에 그대로 두고 집필자가 읽어 쓴다(현행) — 93KB 노이즈를 매번 올려야 하고, 같은 원본에서 같은 결과가 두 번 나오지 않는다.
  • 원본 → MDX 직행(2계층) — 교정본이 곧 발행물이라 재생성이 불가능하다. 카드 요구사항 ③ 을 정면으로 어긴다.
  • L2 를 JSON/YAML 로 — 기계 친화적이지만 사람이 못 고친다. 정본은 사람이 고치는 물건이라는 전제와 충돌한다.

열린 위험 둘

  • 표본이 1건이다. 다른 export 형식(ChatGPT · Claude · 평문 붙여넣기)이 오면 S1 의 정규화 규칙이 흔들린다. 그래서 파서를 형식별 어댑터로 나누고, 모르는 형식은 추측하지 않고 실패시킨다.
  • KAN-067 과 맞물린다. 그 카드의 대담 준비 노트가 어디에 앉을지가 정해지면 raws/talks/<slug>/ 안에 prep.md 로 들어올 수 있다. 지금은 자리만 비워 둔다.

루트 독립성

루트 카드에 scope가 하나도 적혀 있지 않아 독립성을 판정할 수 없습니다. doc-edit으로 카드 문서 frontmatter에 scope를 넣어 주세요.

이 카드가 속한 루트는 다른 루트와 경로가 겹치지 않습니다. 병렬로 수행해도 충돌하지 않습니다.

경로 겹침은 신호이지 판정이 아닙니다. DB 스키마·환경변수·패키지 매니페스트·공유 API 계약처럼 경로에 드러나지 않는 의존은 여기 잡히지 않습니다.

실물 원본으로 도는 완주는 하지 않는다 (유저 판정 2026-08-18). 유일한 실물 원본 raws/talks/ddd-entry-contradiction 은 답변 5개가 잘려 있어(유실 7,527 B = 26.8%) 파이프라인이 정당하게 거부한다. 다시 뽑을지 물었고 "불완전한 표본을 굳이 활용할 필요 없다"는 답을 받았다. 따라서 완주 검증은 위 3번(픽스처 원본 → 봉인 → 굽기 → 해시 불변)이 정본이고, 이 카드에 미결로 남는 것은 없다.
