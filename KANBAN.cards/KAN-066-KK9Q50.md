# KAN-066-KK9Q50 — 폭신 대담: 대화 원본 → 정형 구조화 저장 기능 (원문 보존 포함)

## 전략
<!-- 왜 이 접근인가 · 제약 · 버린 대안. 사람이 자유롭게 편집한다. -->

**입력의 실물을 먼저 봤다.** `raws/ddd-transaction-account-discussion.mdx` 가 유일한
대화 원본 표본이고 93KB 다. 그 안은 중첩 JSON 그래프(`{id, step_index, source, type,
content, tool_calls, children}`)이며 `source` 는 `USER_EXPLICIT` · `MODEL` · `SYSTEM`,
`type` 은 `USER_INPUT` · `CONVERSATION_HISTORY` · `EPHEMERAL_MESSAGE` 등으로 갈린다.
사람의 발화보다 시스템 프롬프트 · 도구 호출 · 플래너 잡음이 훨씬 많다. 이 상태로는
`<QA n q>` 골격에 못 넣고, 매번 집필자 컨텍스트에 93KB 를 통째로 올려야 한다.

**목적지도 이미 정해져 있다.** `.claude/authoring/specs/polssin-daedam/spec.json` 의
`sections` 가 `frontmatter` · `qa`(repeat) · `pullquote` 셋이고, 원칙 SP1(`n` 은 1부터
연속) · SP4(PullQuote 는 요약이 아닌 도달점, 1~2개) · SP5(`template: talk` · `series` ·
`order`) · SP6(`author` 는 인터뷰어)은 **전부 기계가 검사할 수 있는 계약**이다.
즉 발행물은 사람이 손으로 쓸 것이 아니라 **구워야 할 것**이다.

### 3계층으로 나눈다

카드가 요구한 "원문/교정본 2계층"에 **발행물 1계층을 더해 3계층**으로 간다.
2계층으로 끝내면 교정본이 곧 발행물이 되어, 발행물에 손을 대는 순간 "다시 굽기"가
깨지기 때문이다.

| 층 | 무엇 | 어디 | 누가 고치나 |
|---|---|---|---|
| L1 원문 | 받은 그대로. 불변 | `raws/talks/<slug>/source.<ext>` + `source.json` | 아무도 |
| L2 정형본 | 노이즈 제거 + 교정된 정본 | `raws/talks/<slug>/talk.md` | 사람 · AI |
| L3 발행물 | 파생. 손대지 않는다 | `src/content/posts/talk-<slug>.mdx` | 빌더만 |

L1→L2 는 판단이 드는 일(무엇이 질문이고 무엇이 잡음인가, 톤앤매너·비문·맞춤법)이라
**스킬**이 맡는다. L2→L3 는 계약 검사와 치환뿐이라 **스크립트**가 맡는다.
"스킬로 만들지 스크립트로 만들지"는 양자택일이 아니라 이 경계선의 문제였다.

### 굳힌 판단 넷

1. **L2 는 markdown 이다 (JSON·YAML 아님).** 대담 정본은 사람이 계속 손볼 물건인데
   긴 한국어 답변을 JSON 이스케이프나 YAML 블록 스칼라에 가두면 편집이 무너진다.
   대신 형식이 흐물해지지 않도록 **Zod 파서**로 계약을 잡는다 — `src/lib/viz/schema.ts`
   가 ```viz``` 블록에 쓴 것과 같은 방식이다.
2. **저장 위치는 `raws/talks/<slug>/` 다.** `raws/README.md` 가 raws 를 "사용자가 직접
   작성하는 공간"으로 정의하고 `raws/_proceeded/` 로 봉인하는 관례가 이미 있다.
   별도 루트 디렉터리를 새로 파면 유저 입력의 입구가 둘이 된다.
3. **`init-post --talk` 와 합치지 않는다.** 그쪽은 원본 없이 바로 쓰는 **빈 스켈레톤**
   경로이고 이쪽은 **내용이 찬 것을 굽는** 경로다. 진입점이 다르므로 둘 다 남기고,
   `src/templates/talk-episode.mdx` 를 두 경로의 단일 소스로 공유한다.
4. **L3 는 사람이 안 고친다.** 고치고 싶으면 L2 를 고쳐 다시 굽는다. 이 규약이 없으면
   카드가 요구한 "개선 방향이 바뀔 때 다시 굽는다"가 첫 수정에서 죽는다.

### 버린 대안 셋

- **원본을 raws 에 그대로 두고 집필자가 읽어 쓴다**(현행) — 93KB 노이즈를 매번 올려야
  하고, 같은 원본에서 같은 결과가 두 번 나오지 않는다.
- **원본 → MDX 직행(2계층)** — 교정본이 곧 발행물이라 재생성이 불가능하다. 카드
  요구사항 ③ 을 정면으로 어긴다.
- **L2 를 JSON/YAML 로** — 기계 친화적이지만 사람이 못 고친다. 정본은 사람이 고치는
  물건이라는 전제와 충돌한다.

### 열린 위험 둘

- **표본이 1건이다.** 다른 export 형식(ChatGPT · Claude · 평문 붙여넣기)이 오면 S1 의
  정규화 규칙이 흔들린다. 그래서 파서를 형식별 어댑터로 나누고, 모르는 형식은
  **추측하지 않고 실패시킨다**.
- **KAN-067 과 맞물린다.** 그 카드의 대담 준비 노트가 어디에 앉을지가 정해지면
  `raws/talks/<slug>/` 안에 `prep.md` 로 들어올 수 있다. 지금은 자리만 비워 둔다.

## 실행 계획
<!-- `S<n>`은 고정 id — 이름을 바꾸지 않는다. 체크 상태는 doc-step 이 갱신한다. -->

- [ ] `S1` 원본 정규화 규칙 확정 — `raws/ddd-transaction-account-discussion.mdx` 를 표본으로 노이즈 계층(`SYSTEM`·`EPHEMERAL_MESSAGE`·`tool_calls`·`USER_SETTINGS_CHANGE`)을 전수 분류하고 "무엇을 버리고 무엇을 남기는가"를 규칙 문서로 고정. **완료 기준**: 규칙 문서 + 표본에서 살아남은 발화 수·바이트 수 실측값이 문서에 박힌다
- [ ] `S2` L1 원문 보존 규격 — `raws/talks/<slug>/` 레이아웃과 `source.json`(출처·모델·수집일·형식·sha256) 스키마 확정. **완료 기준**: 표본 1건을 실제로 그 구조로 앉히고, 해시 재계산이 기록값과 일치
- [ ] `S3` L2 정형 스키마 + 파서 — `talk.md` 문법(frontmatter + Q/A 마커) 정의와 `src/lib/talk/talkSource.ts`(Zod). **완료 기준**: 표본 파싱 성공 + 위반 케이스 5종(n 불연속·q 누락·PullQuote 3개·series 누락·author 가 교수님)이 각각 **서로 다른** 에러 메시지로 실패
- [ ] `S4` L2 → L3 빌더 — `scripts/build-talk.ts` 가 `talk.md` 를 `src/content/posts/talk-<slug>.mdx` 로 굽는다. SP1·SP4·SP5·SP6 계약 검사 내장, 템플릿은 `src/templates/talk-episode.mdx` 공유. **완료 기준**: 표본을 구워 `bun run build` 통과 + `check-post-markers`·`check-emphasis --dist` 통과
- [ ] `S5` 검증기 — `scripts/verify-talk.ts` + `package.json` 의 `talk:verify`. L2↔L3 어긋남(손으로 고친 발행물)과 L1 해시 불일치를 잡는다. **완료 기준**: 일부러 깨뜨린 3케이스가 전부 비0 종료, 정상 케이스는 0
- [ ] `S6` `talk-ingest` 스킬 — 원본 투입 → L1 봉인 → L2 초안(노이즈 제거·질문 재구성) → `authoring-kit` 의 `polssin-daedam` spec + `ppangtolab-prof` voice 로 톤앤매너·비문·맞춤법 교정 → `build-talk` 호출. **완료 기준**: 표본 1건이 원본부터 발행 가능한 MDX 까지 한 흐름에 통과하고, L1 이 한 바이트도 안 바뀐다
- [ ] `S7` 접점 문서화 — `CLAUDE.md` 폭신 대담 절, `init-post` 스킬의 경계 한 줄, `.claude/authoring/paths.json` 의 `dirs.talk`. **완료 기준**: 세 곳 갱신 + `bun run build` 재통과

## 검증
<!-- 무엇을 실행해 무엇이 나오면 이 카드가 끝난 것인가. -->

표본 `raws/ddd-transaction-account-discussion.mdx` 를 실제 입력으로 써서 아래가 전부
초록이면 끝난 것으로 본다. 하나라도 비0이면 미완이다.

```bash
bun run talk:verify        # L1 해시 · L2 스키마 · L2↔L3 일치
bun scripts/build-talk.ts raws/talks/<slug>/talk.md --check   # 다시 구워도 결과가 같은가
bun run build              # 대담 글이 포함된 채로 전 페이지 빌드
bun scripts/check-post-markers.ts
bun scripts/check-emphasis.ts && bun scripts/check-emphasis.ts --dist
bunx tsc --noEmit
```

**눈으로 확인할 것 셋** (스크립트가 판정 못 한다).

1. 구워진 MDX 를 `astro preview` 로 열어 대담 레이아웃이 뜨는가 — 배너 · 화자 듀오 ·
   오늘의 질문 목차가 `q` 에서 자동 생성되는가.
2. L2 를 한 문장 고치고 다시 구웠을 때 그 문장만 바뀌는가(재현성).
3. L1 원문 파일의 mtime·해시가 파이프라인 전 구간에서 안 바뀌는가.
