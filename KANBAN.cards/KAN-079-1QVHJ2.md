# KAN-079-1QVHJ2 — 토큰 게이트를 래칫에서 하드월로 승격한다 — 조건이 KAN-077 로 처음 충족됐다

## 전략
<!-- 왜 이 접근인가 · 제약 · 버린 대안. 사람이 자유롭게 편집한다. -->

**하드월 승격은 판정 규칙 한 줄이 아니라 넷을 함께 바꾼다.** 「늘면 실패」를 「있으면 실패」로
고치는 것만으로는 게이트가 조용히 무력화된다 — 기준선 파일과 `--update-baseline` 이 아직
「지금 수를 굳히는」 장치로 남아 있어, 위반 하나를 기준선에 박으면 그대로 통과한다.
지금은 그것이 정상 동작이지만(래칫) 승격 뒤에는 **유일한 회피 경로**가 된다.

1. **판정** — `scripts/lib/tokens/baseline.ts` 의 `ratchet()` 이 기준선 대비 증감을 보는
   자리를 **절대 0** 판정으로 바꾼다. 무는 것은 지금과 같은 둘(위반·드리프트)이고
   대상 집합도 같다(제외분 뺀 `scored`).
2. **기준선 파일의 역할** — 「지금 수」에서 「0 이어야 한다」로 바뀐다. 위반·드리프트 칸은
   존재 자체가 모순이 되고, 파일에 남아 계속 일을 하는 것은 둘이다 —
   `selfTestFaults`(줄면 실패, KAN-076) 와 `srcFiles`(범위가 바뀌었다는 알림).
   정보 집계(준수·판정 불가·정당한 예외)를 계속 둘지가 **정할 것 ①**이다.
3. **`--update-baseline` 의 문** — 위반·드리프트가 있는 상태에서 부르면 거부해야 한다.
   안 닫으면 「고치는 법」이 여전히 그 플래그를 가리키고, 게이트를 피하는 가장 짧은 길이 된다.
   처분이 **정할 것 ②**다.
4. **실패 보고** — 지금 구조는 「어느 칸이 늘었는가」로 시작해 **늘어난 파일만** 자리 목록을
   낸다(`baseline.ts:145`). 하드월에는 「늘어난 칸」이라는 개념이 없으므로 무는 자리를
   **전량** `파일:줄 속성: 값 — 판정` 으로 낸다. 인라인 숫자값의 원문 병기(`13(→13px)`,
   KAN-073 S5)는 그대로 가져간다 — 안 그러면 지목한 값이 소스에서 grep 되지 않는다.

**착수 조건은 확인했다 (S1).** `bun scripts/verify-tokens.ts --json` 전건 대조:
판정 5,222건 중 제외분 뺀 5,159건에서 **위반 0 · 드리프트 0**, 준수 4,251 · 판정 불가 894 ·
정당한 예외 14. 남은 무는 판정 4건은 전부 `src/styles/viz.css`(패키지 복제물, 게이트 제외
파일)에 있다 — `margin:28px` 위반 · `margin-top:10px` 드리프트 · `font-size:14px` 위반 ·
`line-height:1.6` 드리프트. 제외분을 세지 않는 것은 하드월에서도 유지한다(생성물·복제물의
리터럴을 사람이 고칠 수 없다).

**CI 위험은 이 카드가 지고 간다.** `.github/workflows/main.yml:78` 에서 게이트가 `build` 잡
안 `astro build`(93) 앞에 돌고 `deploy`(110)가 `needs: build` 로 물려 있다. 승격 뒤 위반
하나가 **사이트 배포까지 멈춘다** — 그것이 하드월의 의도한 의미이므로 워크플로는 안 고친다.
인식층을 넓힌 커밋과 섞지 않은 이유가 이 위험이었다(KAN-077 검토 5항, 유저 승인 2026-08-30).

**버린 대안 셋.**

- **`--warn-only` 를 CI 에 붙인 소프트 하드월** — 게이트가 아무것도 안 막는다. 지금 상태와
  같은 결과이고, 「승격했다」는 기록만 남는다.
- **하드월을 별도 스크립트로 신설** — 판정 코드가 두 벌이 되고 언젠가 한쪽만 고쳐진다.
  이 레포가 이미 겪은 실패 유형이다(KAN-077 이 `scopesOf()` 를 복제하지 않고 직접 부른
  이유가 같다).
- **기준선 파일을 지운다** — `selfTestFaults` 래칫이 함께 죽는다. 인식기를 배열에서 빼면
  게이트가 「덜 검사하면서 통과」하는 자리를 그것이 막고 있고, 카드 ③ 이 지키라고 한 것이다.

**정할 것 (검토 항목으로 낸다).** 카드 메모의 「정당한 예외 10」·「판정 불가 1130」은 낡은
수치다 — 실측은 예외 14 · 판정 불가 894 다(위 S1 대조).

- ① 기준선 파일에 정보 집계를 계속 둘지, `selfTestFaults`+`srcFiles` 만 남길지.
- ② `--update-baseline` 처분 — 위반이 있으면 거부할지, 플래그 이름부터 바꿀지.
- ③ **판정 불가 894 가 위반의 도피처가 되는 것을 무엇으로 막을지.** 하드월 뒤 통과하는
  가장 짧은 길은 위반을 고치는 것이 아니라 **판정 불가로 재분류하는 것**이다. 예외 쪽은
  이미 막혀 있다(근거 문서 위치 필수 + 예외 표 자가검사) — 판정 불가에는 그 문이 없다.

## 검증
<!-- 무엇을 실행해 무엇이 나오면 이 카드가 끝난 것인가. -->

**게이트가 무는가.** 위반을 일부러 심고 지웠을 때 판정이 갈려야 한다 — 통과만 확인하면
죽은 게이트와 다 갚은 게이트가 같은 모양이 된다(이 게이트가 자가검사를 두는 이유와 같다).

```bash
bun run tokens:verify                       # 종료코드 0 · 마지막 줄 「✓ 토큰 게이트 통과」
# 임의 .astro 에 `color: #123456` 한 줄을 심고
bun run tokens:verify; echo "exit=$?"       # 종료코드 1 · 그 파일:줄이 실패 목록에 뜬다
bun run tokens:verify --update-baseline; echo "exit=$?"   # 비0 · 기준선 파일이 안 바뀐다
git diff --stat scripts/tokens-baseline.json              # 비어 있어야 한다
# 심은 줄을 되돌리고
bun run tokens:verify                       # 다시 0
```

**옛 판정이 안 움직였는가.** 인식층을 안 건드리므로 증분이 0 이어야 한다.

```bash
bun run tokens:invariant                    # 종료코드 0
```

**게이트가 작아지지 않았는가.** `selfTestFaults` 가 S5 만큼 오르고 그보다 줄면 실패한다.

```bash
bun run tokens:verify | grep '자가검사'      # 고장 종수가 기준선과 같거나 크다
```

**빌드 회귀.**

```bash
bun run build                                # 통과
```

**문서가 게이트와 같은 말을 하는가.**

```bash
grep -rn "래칫" CLAUDE.md design-concept/UI_CONSISTENCY_AUDIT.md scripts/verify-tokens.ts scripts/lib/tokens/
```

남은 「래칫」이 **이력 서술뿐**이어야 한다 — 지금 동작을 래칫이라고 말하는 자리가 하나도
없어야 하고, 남긴 자리는 S7 이 목록으로 낸다.

**CI 는 안 고쳤다.** `git diff --stat .github/` 가 비어 있어야 한다 — 하드월이 배포를
멈추는 것은 의도한 의미이므로 워크플로를 손보는 것이 이 카드의 일이 아니다.
