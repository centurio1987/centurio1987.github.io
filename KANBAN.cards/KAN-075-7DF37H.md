# KAN-075-7DF37H — 게이트 인식층 — 여러 줄에 걸쳐 쓴 CSS 선언 47건을 판정에 넣는다

## 전략
`extract.ts:58` 의 선언 정규식 `DECL` 이 값 클래스를 `[^;{}\n]` 으로 잡아 **줄바꿈을 넘는
선언이 통째로 판정 밖**이다. 카드 목표가 든 `src/components/Logo.astro:58` 의 세 줄짜리
`box-shadow` 가 그 자리다 — 그 안의 `rgba(32, 38, 74, 0.12)` 는 게이트가 한 번도 본 적이 없다.

### 첫 판단은 이미 정해졌다 — 옛 정규식을 안 고쳐도 열린다

카드 메모가 남긴 판단 항목은 **"옛 `DECL` 을 고쳐야 해서 감사 원자료 3,539 히트와의 대조가
깨진다, 그것을 어떻게 유지할 것인가"** 였다. 실측으로 전제가 뒤집혔다 — 고칠 필요가 없다.

KAN-073 이 세운 인식층 구조를 그대로 쓴다: **`DECL` 을 한 글자도 안 고치고**, 줄바꿈을 받는
별도 패스를 `recognize/` 의 넷째 인식기로 붙여 **새 `src` 라벨**(`ml-decl`)로 낸다. 겹침은
셋으로 막는다 — ① 같은 시작 오프셋에서 `DECL` 이 이미 매치한 것은 건너뛴다 ② 값에 줄바꿈이
없으면 안 낸다(`grid-template-columns:\n  repeat(2, 1fr);` 처럼 콜론 뒤 `\s*` 가 줄바꿈을
흡수해 **이미 잡히는** 자리다) ③ `DECL` 매치가 새 매치 구간 **안에** 들어앉은 경우도 뺀다.

**실측으로 확인했다**(스크래치패드 `probe-invariant.ts` · `probe-overlap.ts`).

| 무엇 | 결과 |
| --- | --- |
| 옛 히트 집합 (`src ≠ ml-decl`) | 변경 전 4,073 → 후 4,073, **`(src·axis·kind·prop·value·file·line·token·excluded)` 키로 바이트 단위 동일** |
| 새 매치 구간 안의 옛 `DECL` 매치 | **0건** (지금은 그렇다 — 보장이 아니라서 ③ 가드를 코드에 박는다) |

그래서 이 카드는 KAN-073 과 **같은 계약**을 진다: 「옛 히트 한 건도 안 움직인다」.
감사 원자료 대조는 깨지지 않고, `UI_CONSISTENCY_AUDIT.md` §6 11항의 "안 여는 이유"는
사실이 아니게 되므로 정정 블록을 붙인다.

### 실측 — 열면 무엇이 들어오는가

**여러 줄 선언 54건 · 20파일**(값에 줄바꿈이 있고 `DECL` 이 못 잡는 것). 감사 §6 11항이 적은
47과 7 차이가 나는데, 그 수를 낸 판정기가 KAN-073 스크래치패드에만 있었고 레포에 안 남아
**원인을 못 짚었다**. 계획을 바꾸는 차이는 아니다 — 게이트가 세는 것은 선언 수가 아니라 히트다.

**판정에 들어오는 히트 173건**, 전부 게이트 대상(생성물 제외분 0 — `motion.css` 의 여러 줄
선언 3건은 `animation`·`transition` 이라 축 표에 없어 히트를 안 낸다).

축은 둘뿐이다 — `color` 141 · `shadow` 32. **래칫 증분은 29**(드리프트 21 + 위반 8)이고
6파일에 모여 있다.

**고유 값은 15개뿐이고 전부 `rgba()` 다.** 드리프트 21건은 `rgba(32, 38, 74, α)`(=`--ink`) 13건과
`rgba(255, 255, 255, α)`(=`--tony-glint`) 7건, `rgba(32,38,74,0.12)` 1건으로 **토큰 값을 rgba 로
전개해 다시 적은 것**이다. 위반 8건은 테이프·크래프트 종이 계열 6색이다.

`viz-frame.css` 와 `PhotoFrame.astro`·`Tape.astro` 가 **같은 표현을 복제**해 들고 있다
(감사 §3-9 가 이미 지목한 자리다) — 한쪽만 고치면 두 지면이 갈린다.

### 무엇을 안 하는가

- **`stroke-width` 81건**(KAN-076) · **상수 승격 리터럴 15건**(KAN-077). 인식 갈래가 다르다.
- **부채 상환을 이 카드에 넣을지는 배치 선택으로 유저가 정한다.** KAN-073 은 인식층만 열고
  기준선을 778 로 다시 세운 뒤 상환을 KAN-074 로 넘겼다. 여기서는 29건 · 6파일 · 값 15개라
  한 배치에 들어갈 크기여서 두 길이 다 성립한다. 배치 문서에 두 관점으로 낸다.

### 무는 제약 셋

1. **인식층 확장과 기준선 갱신은 같은 커밋이다.** 게이트는 `main.yml` 의 `build` 잡에서
   `astro build` **앞**에 돌고 `deploy` 가 `needs: build` 로 물려 있다 — 나누면 그 사이
   푸시에서 사이트 배포가 멈춘다(`CLAUDE.md` 토큰 게이트 절).
2. **자가검사가 기준선 갱신보다 먼저다.** 래칫은 "줄었다"를 통과로 읽어서, 죽은 게이트와 다
   갚은 게이트가 화면에서 같은 모양이다. 새 인식기는 자기 고장 픽스처를 소유하고, 유일성 키
   `(verdict, want, src)` 의 셋째 자리가 `ml-decl` 이라 기존 아홉과 안 겹친다.
3. **하드월 승격은 여기서도 안 한다.** 승격 조건은 「인식층이 다 열린 뒤의 래칫 0」이고
   KAN-076·077 이 남아 있다.

## 검증
<!-- 무엇을 실행해 무엇이 나오면 이 카드가 끝난 것인가. -->
1. **옛 히트 불변** — `bun scripts/verify-tokens.ts --json` 을 변경 전(`git show HEAD:` 격리 사본)과
   후로 각각 떠서 `src ≠ ml-decl` 히트를 `(src·axis·kind·prop·value·file·line·token·excluded)`
   키 집합으로 대조한다. **기대 증분 0.** KAN-073 은 옛 `src` 라벨을 단 히트가 1건 늘어
   화이트리스트를 뒀지만, 이 카드는 `DECL` 을 안 고치므로 화이트리스트가 없다.
2. **겹쳐 세지 않는다** — ① 새 매치 구간 안의 옛 `DECL` 매치 **0** ② 새 `src` 와 옛 `src` 의
   `(file, line, value)` 교집합 **0**. 1번은 옛 히트만 봐서 겹침을 못 잡는다.
3. **자가검사** — 맨몸 실행으로 「정상 1 + 고장 10종, 사유 10가지」. 유일성 키
   `(verdict, want, src)` 의 셋째가 `ml-decl` 이라 기존 아홉과 안 겹친다.
   **기준선 갱신보다 먼저 한다** — 죽은 게이트와 다 갚은 게이트가 화면에서 같은 모양이다.
4. **게이트가 실제로 문다** — 여러 줄 선언에 토큰 밖 색을 새로 심은 픽스처가 `ml-decl` 경로로
   위반 판정을 받는다. 「173건이 들어왔다」는 인식만 증명하지 판정을 증명하지 않는다.
5. **화면 변화 0** — 배치1·2 는 `scripts/` 와 문서만 고치므로
   `git status --porcelain src/ public/` 가 **비어 있음**으로 갈음한다.
   배치3 을 하면 `src/` 가 바뀌므로 그때는 **`bun run render:compare` 가 정본**이다(KAN-074).
6. **회귀 없음** — `bun run build` · `viz:verify` · `deco:verify` · `width:verify` · `talk:verify` ·
   `check-post-markers` · `check-emphasis`(+`--dist`) · `tsc --noEmit` 신규 0.
   `graph:verify` 는 `src/data`·`src/content` 를 안 건드리므로 대상 밖이다.
7. **CI 가 안 빨개진다** — 인식층 확장과 기준선 갱신이 **같은 커밋**에 들어간다.
   게이트는 `build` 잡에서 `astro build` 앞에 돌고 `deploy` 가 `needs: build` 로 물려 있다.
