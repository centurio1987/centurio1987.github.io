# KAN-067-NH9SDQ — 폭신 대담에서 사용할 주제는 아래와 같다. 미리 주제에 대해 리서치를 하고, 대화를 대비한 준비를 해둬라.

## 전략
이 카드의 산출물은 **글이 아니라 대화 준비물**이다. 폭신 대담은 사용자가 실제로 나눈 대화를
L1 원문으로 봉인해 굽는 구조(KAN-066)라, 대화 전에 만들 수 있는 것은 발행물이 아니라
**사용자가 대화에 들고 들어갈 것** — 질문 순서, 이미 낸 의견 셋의 사전 판정, 예상 반론,
숫자·규격 앵커 — 뿐이다. 그래서 리서치를 문서로 정리하는 데서 멈추지 않고 거기까지 간다.

**세 자리를 나눈다.**

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| 리서치 원본·위키 | `~/blog-research/` | `research` 스킬의 규약. 위키로 ingest 되면 다른 글도 재사용한다 |
| 대담 준비 노트 | `raws/talks/_prep/<slug>.md` | 대담의 자리에 두되 층은 섞지 않는다 |
| 대화 원본·정형본·발행물 | `raws/talks/<slug>/` · `src/content/posts/` | **이 카드에서 만들지 않는다.** 대화가 아직 없다 |

`_prep/` 을 밑줄로 시작하는 이유는 `scripts/build-talk.ts:49` 가 `_`·`.` 로 시작하는 이름을
slug 목록에서 빼기 때문이다 — `raws/talks/<slug>/` 안에 준비 노트를 넣으면 `talk:verify` 가
"정형본 없는 대담"으로 세거나 L1/L2 의 자리와 뒤섞인다.

**버린 대안 셋.**

- 준비 노트를 `draft/` 에 두기 — `draft/` 는 발행 직전 산출물의 자리다. 준비물은 발행 후보가 아니다.
- 리서치를 이 저장소 `raws/` 에 두기 — 두 저장소가 같은 자료를 각자 들면 갈라진다.
  집필 규칙이 세 저장소로 갈라졌다가 `authoring-kit` 으로 합친 것이 같은 실패였다.
- 대담 원고를 미리 써 두기 — 원문 위조다. 폭신 대담의 계약은 "실제 대화가 원문"이고,
  준비 노트가 답까지 적어 두면 대화가 그 노트의 낭독이 된다.

**두 주제는 한 에피소드가 아니다.** ①은 프론트엔드 반응성(성능축 + UX축), ②는 백엔드
질의 지배 성능이다. 겹치는 곳(캐시 계층·프리컴퓨트)이 있지만 독자가 따라오는 경로가 달라
준비 노트도 둘로 나눈다. 실제로 한 회차로 합칠지는 대화가 끝난 뒤 정한다.

## 검증
```bash
bun run talk:verify        # _prep/ 이 slug 로 오인되지 않는가 — 대담 집계가 기존과 같아야 한다
bun run build              # 회귀 없음
ls raws/talks/_prep/       # README.md + 준비 노트 2건
```

- `~/blog-research/wiki/topics/` 에 주제별 topic 페이지가 생겼고 `index.md`·`log.md` 가 갱신됐다.
- 준비 노트 두 건이 각각 다섯 항(질문 순서 · 의견 판정 · 예상 반론 · 앵커 · 용어)을 모두 갖췄다.
- 유저 의견 셋이 **각각** 판정돼 있다 — "대체로 맞다" 같은 뭉뚱그림이 없다.
- 노트의 모든 수치·규격에 출처가 붙어 있다. 출처 없는 값은 적지 않는다.
- `src/content/posts/` 와 `raws/talks/<slug>/` 는 이 카드에서 **바뀌지 않았다**(대화 전이다).
