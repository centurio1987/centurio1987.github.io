# S4 산출 — 예외 판정 (KAN-069-M724GH)

판정기 `s4-classify.py` · 원자료 `s4-classify.json` (스크래치패드).
보조 판정기 `s4-fallback.py` · `s4-fallback.json` — S3 이 통째로 걷어낸 `var(--x, <fallback>)` 자리.

## 1. 판정 갈래는 셋이 아니라 다섯이다

카드 「실행 계획」 `S4` 는 셋(정당한 예외 / 드리프트 / 위반)을 적었다. 다섯으로 늘렸고, 근거는
배치1 인계사항 3번이다 — 간격·글자크기·그림자·z-index 는 **대조할 토큰이 아예 없어서**
"토큰을 안 썼다"가 성립하지 않는다. 이것을 위반에 섞으면 위반 2,634건이라는 틀린 수가 나오고,
정작 고칠 수 있는 580건이 그 안에 묻힌다. 「측정 제외」는 S3 §7-2 가 미리 적어 둔 축 누수다.

| 판정 | 뜻 | 건수 |
|---|---|---:|
| **준수** | `var(--x)` 로 토큰을 썼다 | **858** |
| **드리프트** | 토큰이 있는데 값을 다시 적었다 | **71** |
| **위반** | 그 축에 토큰 체계가 있는데 토큰 밖 값이고, 근거 문서를 못 걸었다 | **580** |
| **정당한 예외** | 근거 문서의 위치를 걸 수 있다 | **3** |
| **토큰 미존재** | 대조할 토큰 자체가 없는 축 — 위반이 아니라 체계의 공백이다 | **1,977** |
| 측정 제외 | 색 축 shorthand 에 섞인 비색 값(그라디언트 정지점 등) | 50 |
| | **합계 = S3 총 히트** | **3,539** |

**판정 대상(준수+드리프트+위반+예외) 1,512건 중 준수는 858건 = 56.7%.**

## 2. S3 원자료에 얹은 보정 셋

S3 은 분류만 했고 그 한계를 §7 에 적어 뒀다. 판정하려면 셋을 고쳐야 했다.

| 보정 | 무엇 | 효과 |
|---|---|---|
| (1) 축 누수 | `border: 1px solid var(--border)` 의 `1px` 이 color 축으로 들어왔다 | 216건을 색에서 빼내 **stroke 축 166건 + 잡음 50건**으로 갈랐다 |
| (2) 표기 차이 | S3 은 문자열 비교라 `#3E6B4F` 와 `#3e6b4f` 를 다른 값으로 봤다 | 드리프트 **+14건**(D2) |
| (3) rgba 전개 | `rgba(32,38,74,α)` 는 `--ink`(`#20264A`)를 푼 것이다 | 드리프트 **+3건**(D3) |

(1)이 가장 크다 — S3 의 `--stroke` 대조가 통째로 안 돌고 있었다. `--stroke: 1.5px` 가 있는데
`1.5px` 를 리터럴로 적은 자리가 **21건**, 토큰 밖 선 굵기가 **145건**(`1px` 129 · `3px` 8 · `2px` 7)이다.

**이미 토큰화돼 판정 대상이 아닌 "예외"가 셋 더 있다** — 예외로 세지 않은 이유가 각각 다르다.

## 7. 별도 확인 둘 — S3 이 못 본 자리

### 7-1. `font-family` 리터럴은 0건이다

S3 의 리터럴 정규식은 `#hex` · `rgb()` · 단위 붙은 수 · 맨 숫자만 잡는다. `font-family` 값은
따옴표 문자열이라 **한 건도 안 잡혔다** — 즉 "font-family 드리프트 0건"은 측정이 아니라 미측정이었다.
따로 셌다: `src/**` 에서 `var(--` 를 안 쓴 `font-family` 선언은 **0건**(`tokens.css` 자신 제외).
폰트 축은 실제로 깨끗하다.

### 7-2. `var(--x, fallback)` 108자리 중 fallback 이 토큰과 갈리는 것이 23건

S3 은 `var(...)` 를 통째로 지우므로 이 자리는 판정에 안 들어왔다. **fallback 이 토큰과 갈리면
그 스타일시트를 안 들여온 지면에서만 다른 값이 뜬다** — 두 지면을 나란히 놓기 전까지 안 보인다.

`--deco-t3` 처럼 선택자마다 다시 정의되는 **스위치 5종**(`--deco-op`·`--deco-t3`·`--deco-t4`·
`--deco-wob`·`--shell-max`)은 fallback 이 "기본 상태"라 대조 대상이 아니다. 값 토큰 119종만 쟀다.

| 결과 | 건수 |
|---|---:|
| 일치 | 42 |
| **불일치** | **23** |
| 스위치 — 대조 제외 | 15 |
| 지역 변수 — 대조 제외 | 28 |

불일치 23건은 **발동 여부로 갈린다.** `tokens.css` 는 `global.css:1` 이 들여오고 그것을
`BaseLayout.astro:2` 가 들여와 **전 페이지에 있다** — 그래서 tokens 토큰의 fallback 은 죽은 값이다.
`deco.css` 는 쓰는 쪽에서만 들여오므로(DECO_KIT.md:40) 데코 토큰의 fallback 은 **실제로 발동한다.**

| 갈래 | 건수 | 자리 | 성격 |
|---|---:|---|---|
| **살아 있는 불일치** | **4** | `Doodle.astro:319,325` (`--deco-crayon-blue` fb `var(--accent)` ≠ `#2540e8`) · `:390` (`--deco-crayon-red` fb `var(--deco-red)` ≠ `#e8564e`) · `design/frame-picks.astro:330` (`--deco-pink` fb `#d98da6` ≠ `#e0919f`) | `deco.css` 를 안 들여온 지면에서 **다른 색이 뜬다.** 앞의 셋은 DECO_KIT.md:200 이 정한 "시안 hex fallback" 규칙과도 어긋난다 |
| 죽은 불일치 | 19 | `--radius-md` fb `8px`≠`12px` ×4 · `--font-code` fb `monospace` ×7 · `--ease` fb `ease` ×3 · `--card-radius` fb `12px`≠`14px` · `--page-pad` fb `24px`≠`clamp(…)` · 그 밖 | 지금은 안 뜬다. 그러나 **틀린 값이 코드에 적혀 있어** 다음 사람이 그것을 토큰 값으로 읽는다 |

`frame-picks.astro:398,449,477,489` 의 `var(--radius-md, 8px)` 는 `--radius-sm` 값을 `--radius-md`
의 대체로 적은 것이라, 죽은 값이지만 **읽는 사람을 틀리게 만드는 종류**다.

## 8. 이 판정이 안 본 것

1. **`.mdx` 31개 · `.ts` 28개** — S3 이 그은 범위 밖이다(S3 §7-3).
2. **`public/**` 의 SVG·이미지 안 색** — 대상이 아니다.
3. **다크 모드** — 이 사이트는 단일 테마라 판정 축이 없다.
4. **이름 색**(`red`·`white`·`transparent`·`currentColor`) — S3 정규식이 안 잡는다(S3 §7-1).
   `#fff`/`#ffffff` 28건은 잡혔지만 `white` 표기는 안 잡혔다.
5. **계산값·조건부 값** — 어느 상태에서 쓰이는지는 안 남는다(S3 §7-5).
6. **`50%`(radius 25건)를 위반으로 둔 것은 규칙 때문이다.** 원형 마스크는 스케일 값이 아니라 CSS
   관용 표현이지만, 그 사실을 적어 둔 문서가 없다. 규칙대로 위반이고 고치는 값은 한 줄이다(S5).

## 10. 보강 — 「토큰 미존재」 1,977건 중 987건은 실은 **문서 규칙 위반**이다

**S4 를 닫은 뒤 발견해 다시 잰 것이다.** 판정기가 대조 상대를 `tokens.css` 에서만 찾은 탓에
간격·글자 크기를 「토큰 미존재」로 묶었는데, `DESIGN_CONCEPT.md` 를 읽어 보니 **둘 다 규칙이
적혀 있다.** 토큰이 없다는 것과 규칙이 없다는 것은 다르다 — 규칙이 있으면 지켰는지 물을 수 있다.
