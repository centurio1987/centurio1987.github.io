**순서가 곧 이 WP 의 내용이다.** 셋을 이 차례로 한다.

**(가) 옛 `AXIS` 맵 확장 — 1건짜리 명시 변경.**
`extract.ts:20-34` 에 camelCase 를 더한다. 이것만은 **옛 히트를 움직인다** — 값을 줍는 것이
새 인식기가 아니라 기존 `JSXOBJ` 이기 때문이다. 실측 증분은 정확히 1건:

```
src/components/posts/vpn-anatomy-2/NonceReuseLab.tsx:306   minWidth: "10rem"
```

(`marginLeft: "auto"` 5건은 `LITERAL` 이 안 물어 0건이다.) 이 1건을 화이트리스트로 코드나
검증 스크립트에 명시하고, 그 밖의 차이가 0 임을 (나)에서 확인한다.

**(나) 옛 히트 대조.** `bun scripts/verify-tokens.ts --json` 을 `git show HEAD:` 격리 사본과
지금 워크트리에서 각각 떠서 히트를 `(file, line, prop, value)` 키 집합으로 대조한다.
**`src` 로 거르지 않는다** — (가)가 옛 `src` 라벨을 단 히트를 늘리므로 필터로는 안 걸린다.
함께 확인: 새 `src` 셋과 옛 셋의 `(file, line, value)` 교집합이 **0**.

**(다) 자가검사 생존 확인 → 기준선 갱신.** 맨몸 실행으로
"정상 1 + 고장 9종, 사유 9가지"(유일성 키 `(verdict, want, src)`)를 본 **뒤에**
`--update-baseline` 을 부른다. 순서를 뒤집으면 안 된다 — 래칫은 "줄었다"를 통과로 읽으므로
**죽은 게이트와 다 갚은 게이트가 화면에서 같은 모양**이고, 게이트가 살아 있음을 먼저
증명해야 새 기준선이 뜻을 갖는다.

**완료 기준**: 옛 히트 증분이 화이트리스트 1건뿐이고 교집합이 0 이며,
자가검사 9종 확인 뒤 `bun run tokens:verify` 가 exit 0 · "기준선과 같다".
