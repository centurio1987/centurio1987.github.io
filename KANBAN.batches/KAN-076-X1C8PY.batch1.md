## 1. 작업 패키지

### WP1 · `S1` 실측을 레포에 굳힌다

`stroke-width` 자리 전수와 각 자리의 SVG 좌표계를 뽑는다. 카드 메모·감사 §6-12 의
「viewBox 유무가 갈림선」이 실측과 안 맞는다는 것을 **출력으로** 세운다.

- 스캔 범위(`.astro`·`.tsx`·`.css`) 안에서 네 형태를 모두 센다 — svg 속성 ·
  CSS 선언 · JSX 표현식 · style 객체.
- 자리마다 감싸는 `<svg>` 의 `viewBox` · `width` · `height` 를 붙인다.
- 범위 밖 `.ts` 는 따로 세어 「이 카드 밖」으로 적는다(감사 §6-1).

**완료 기준**: 출력에 ① 범위 안 자리 수와 형태별 내역, ② **viewBox 없는 SVG 0개**,
③ **정적 배율 1 인 자리 0개**, ④ 범위 밖 `.ts` 건수가 나온다. 이 넷이 S2·S3 의 전제다.

### WP2 · `S2` 다섯째 인식기 `recognize/svgStroke.ts`

`src` 라벨 `svg-stroke`. **옛 정규식(`DECL`·`ATTR`·`JSXOBJ`)과 `AXIS` 표는 한 글자도 안 고친다.**

- `Hit["src"]` 유니온에 `"svg-stroke"` 를 더한다(`lib/tokens/types.ts`).
- `Recognition`·`Hit` 에 좌표계 필드를 더한다 — 무엇을 실었는지가 판정의 입력이므로
  `prop` 문자열에 숨기지 않는다(`rawValue` 를 만든 것과 같은 이유).
- 좌표계 판별: 자리 앞의 가장 가까운 `<svg …>` 여는 태그를 찾아 `viewBox`·`width`·`height`
  를 읽는다. **못 찾으면 「미상」이고 미상은 사용자 단위로 다룬다** — `VizNote.tsx:47`
  처럼 style 객체가 `<svg>` 위에 선언된 자리와 `PosterHero.tsx:124` 처럼 패키지
  컴포넌트(`<Canvas viewBox=…>`)가 SVG 를 그리는 자리가 그것이다. 못 찾은 것을 px 로
  넘기면 가짜 위반이 된다.
- CSS 선언 자리는 `cssChunks` 안에서만 돈다(밖에서 돌면 JSX 가 CSS 로 읽힌다).
- **겹침 가드**: 옛 경로는 `AXIS` 에 `stroke-width` 가 없어 이 축을 영영 못 내므로
  구조적으로 안 겹친다. 그래도 `tokens:invariant` 의 겹침 검사(`(file,line,value)` 교집합)로
  확인한다 — 「구조적으로 안 겹친다」는 논증이지 실측이 아니다.

**완료 기준**: 네 형태 각각의 실제 자리가 히트로 나온다 —
`Doodle.astro:437`(속성 `9`) · `GraphExplorer.tsx:1878`(CSS `4px`) ·
`GraphExplorer.tsx:1308`(JSX `{2}`) · `VizNote.tsx:47`(객체 `2.6`). 각 히트가 좌표계를
들고 있고, 앞 세 자리는 viewBox 를 찾고 넷째는 「미상」이다.

### WP3 · `S3` 판정 — 단위로 가른다

- 추출 축 `Axis` 에 `"stroke"` 를 더한다. 옛 경로는 이 축을 못 내므로 옛 집합이 안 움직인다.
- `extract.ts` 의 `classify()` 에서 맨 숫자를 버리는 필터에 `stroke` 예외 한 줄
  (`stroke-width="9"` 가 여기서 죽는다). 옛 경로가 `stroke` 축을 못 내므로 옛 히트는 불변.
- `color.ts` 가 `hit.axis === "stroke"` 를 받는다. 단위가 **CSS px** 면 기존 stroke 판정
  (`--stroke*` 대조 → 드리프트/예외/위반), **사용자 단위**면 `판정 불가` 이고 사유에
  좌표계를 적는다. 사유는 `stroke 축` 으로 시작해야 한다 — `baseline.ts` 의 `judgeAxis`
  가 사유 접두로 축을 되뽑는다.

**완료 기준**: `bun run tokens:verify` 가 종료 0 으로 끝나고
`stroke / 판정 불가` 가 새로 서며 **위반·드리프트 증분이 0** 이다.
(래칫은 위반·드리프트만 문다 — 판정 불가가 느는 것은 스캔 범위를 넓혔다는 뜻이라
`baseline.ts` 가 이미 실패로 안 본다.)

## 3. 리스크

- **`Axis` 유니온 확장이 옛 경로로 새는 것.** `AXIS` 표에 `stroke-width` 를 보태면
  그 값을 줍는 것이 새 인식기가 아니라 기존 `DECL`/`ATTR` 이 되어 옛 집합이 움직인다.
  `propAxis.ts` 머리주석이 「여기에 보태지 마라」로 못박은 자리다. **표를 안 건드리는 것이
  이 배치의 첫 제약이고, 지켰는지는 `S5` 의 `tokens:invariant` 가 판정한다.**
- **좌표계를 못 찾은 자리를 px 로 넘기는 것.** 미상 → 사용자 단위가 기본값이어야 한다.
  거꾸로 두면 `PosterHero.tsx:124` 의 `strokeWidth: 2` 가 `--stroke-bold`(2px)와 값이 같아
  **드리프트로 잡히는데**, 실제로는 래스터 2배라 화면에서 4px 다. 조용히 틀리는 종류다.
- **예산.** WP2 가 이 배치의 무게 중심이다(좌표계 판별이 네 형태마다 다르다).
  넘칠 것 같으면 `S3` 을 배치2 로 넘긴다 — 다만 그러면 `tokens:verify` 가 한 번도 안 돈
  상태로 배치가 닫히므로, **넘기기 전에 `--warn-only` 로라도 한 번 돌려 인식 수를 남긴다.**
