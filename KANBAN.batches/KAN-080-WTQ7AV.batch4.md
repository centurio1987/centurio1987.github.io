## 1. 작업 패키지

세 WP 가 하는 일이 **같다.** 다른 것은 대상 구획뿐이라 아래 규약을 셋이 공유하고, WP 별로는
그 구획의 수와 특이점만 적는다.

### 공통 규약 — 무엇을 무엇으로 바꾸는가

**크기(`fontSize`)는 안 건드린다** — 이미 100% 토큰이다. 움직이는 것은 넷이다.

| 축 | 지금 | 무엇으로 | 근거 |
|---|---|---|---|
| 굵기 | `600` (위반 66 전량이 이 값) | `var(--font-weight-bold)` = **700** | §5 「`600` 과 `800` 은 700 으로 접는다」 |
| 행간 | 1.55·1.6·1.65 → ui / 1.7·1.8 → read / 1.4·1.5 → sub / 1.15·1.2·1.3·1.35 → title | `var(--font-leading-*)` | §5 6단 + **동률은 작은 쪽으로** |
| 자간 | px 혼용 · 0.06em 류 | `var(--font-track-*)` | §5 4단, **단위는 em 하나** |
| 얼굴 | raw `"monospace"` 등 42자리 | `var(--font-code)` | §5 · `tokens.css:227` |

**접기가 애매한 값 둘은 착수해서 그 자리를 보고 정하고, 정한 근거를 커밋 메시지에 적는다.**
① `1.35` 는 title(1.25)·sub(1.45)에서 각각 0.1 인 **동률**이라 규약대로 title 이다.
② 행간 `0` 이 1건 있다 — flat(1)로 접을 것이 아니라 **그 자리가 무엇인지 보고** 판정한다
(0 은 「한 줄」이 아니라 「줄상자를 죽인다」라, 아이콘 정렬용이면 접으면 위치가 움직인다).

**`var(--없는토큰)` 은 선언을 통째로 무효로 만들면서 에러를 안 낸다** — 토큰 이름은 위 표에서
복사하지 말고 `src/styles/tokens.css:262-278` 에서 확인한다.

## 3. 리스크

| 무엇 | 어디서 | 어떻게 막는가 |
| --- | --- | --- |
| **`render:compare` 의 exit 1 을 실패로 읽고 되돌린다** | 세 work 전부 | **exit 1 이 정상이다.** `S3` 이 접으므로 값이 움직이고(1.55→1.6), `monospace`→`var(--font-code)` 는 얼굴 자체가 바뀐다(그 속성이 `compare-render.ts:377` 대조 목록에 있다). **판정은 종료코드가 아니라 diff 목록**이고, KAN-072 관례대로 **「값 동일 n · 스냅 m」을 갈라 센다**(`--summary`). 스냅이 §5 표가 예측한 방향·크기인지 본다 |
| **접기 표 밖 값을 눈대중으로 접는다** | 행간 `1.35`(동률) · `0`(1건) | 동률은 **작은 쪽으로**가 §5 규약이라 `1.35`→title 은 결정론이다. `0` 은 규약이 답을 안 주므로 **그 자리를 보고 정하고 근거를 커밋 메시지에 적는다** — 줄상자를 죽이는 자리면 접으면 위치가 움직인다 |
| **`var(--없는토큰)` 이 조용히 선언을 죽인다** | 세 work 전부 | 빌드도 타입도 초록이다. 토큰 이름을 문서에서 복사하지 말고 `tokens.css` 에서 읽고, `render:compare` 의 diff 에 **의도하지 않은 속성**(색·자리)이 섞였는지 본다 |
| 굵기 `600`→`700` 이 11~13px 자리에서 뭉개진다 | `S10`~`S12` 전부(위반 66 전량이 600) | §5 가 이미 판단한 것이다 — 그 크기에서 500 대 400 이 크림 바탕에서 안 갈려 700 으로 접었다. **여기서 다시 판단하지 않는다.** 화면이 바뀌는 것이 의도이므로 `render:compare` 스냅 목록에 들어 있어야 정상이다 |
| **`type:verify` 3층이 새로 빨개진다** | raw 얼굴 42자리 치환 | `--font-code` 스택 끝에 본문 서체가 있어 한글 덮개가 생긴다 — 오히려 **좋아지는 방향**이다. 다만 `"ui-monospace, SFMono-Regular, Menlo, monospace"` 2자리는 OS 얼굴을 명시한 자리라, 치환하면 그 의도가 사라진다. **그 2자리는 값을 보고 정한다** |
| 기준선을 work 마다 조여 그물이 헐거워진다 | 세 work | **배치 끝에서 한 번**이다. work 마다 조이면 그 work 가 다른 축에서 늘린 것이 그 자리에서 기준선이 되어 다음 work 가 못 잡는다 |

**되돌리기**: work 하나 = 커밋 하나 = 태그 `kan/KAN-080-WTQ7AV/S<n>`.
세 work 전부 `src/components/posts/<구획>/` 안에서만 움직이고 파일 겹침이 0 이라 revert 가 깨끗하다.
기준선 갱신은 별도 커밋(`kan/KAN-080-WTQ7AV/batch4`)이라 값 치환과 섞이지 않는다.

## 4. 착수 시점 판단

**3 work 를 그대로 간다.**

**병렬(폭 3)을 접고 직렬로 간다.** 카드 전략이 추천한 오케스트레이션 배치인데, 착수 시점에

2. **병렬이 아끼는 것이 벽시계뿐인데 대는 값이 크다.** 세 work 가 각자 `astro build` +
   Chromium 을 띄워야 하고(`render:compare`), `--ns` 네임스페이스와 포트를 배정해야 하며,
   `tokens-baseline.json` 은 어차피 **배치 끝에서 한 번** 조인다.

   토큰을 지나면 준수이기 때문이다.
