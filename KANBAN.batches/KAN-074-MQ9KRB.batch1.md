카드: [KAN-074-MQ9KRB.md](../KANBAN.cards/KAN-074-MQ9KRB.md) · 범위 `S1` · `S2` · `S3` · `S4`
선행: 없음 (이 카드의 첫 배치)

> **이 문서는 착수 전 계획이다.** 수행 내역은 카드 실행 문서의 「수행 내역」에 있다.

이 배치는 **화면이 한 픽셀도 안 바뀌어야 하는 구간**이다. 그래서 검증의 성격이 다음 배치와
정반대다 — 배치2 는 "무엇이 얼마나 바뀌었나"를 재고, 여기는 **"아무것도 안 바뀌었다"를
증명한다.** 그 증명은 하네스가 살아 있을 때만 뜻이 있으므로 `S1` 이 먼저다.

## 1. 작업 패키지

### WP1 · `S1` 격리 대조 하네스

`scripts/compare-render.ts` 를 만든다. 격리 사본 두 벌(전·후)을 굽고 발행 글 페이지의 모든
요소를 `getComputedStyle` 로 훑어 속성값을 대조한다. **`[style*='hex']` 셀렉터를 쓰지 않고
셀렉터에 리터럴을 안 박는다** — 둘 다 치환 후 조용히 0 이 되는 길이다
(`KANBAN.cards/KAN-072-CPJCT1.md:229`).

격리 사본 규약(전부 KAN-072 실측): `rsync -a --link-dest` 로 하드링크(심링크 `node_modules`
는 vite 가 없는 경로를 만든다) · `--exclude '/dist'` 앵커 · 사본은 레포 **밖**(안에 두면 tsc
가 두 벌로 훑는다) · 자기 파일만 `git show HEAD:<경로>` 로 되돌린다(공유 인덱스 불변) ·
`astro preview` 는 `[::1]` 바인딩이라 `localhost` 로 붙는다 · dist HTML 대조는
`sed -E 's/ uid="[^"]*"//g'` 먼저.

**완료 기준**: 고장 3종을 주입하면 셋 다 **각자 다른 사유로** 물고, 안 주입하면 0건이다.
주입은 두 갈래를 모두 — 토큰 이름 지우기(이름 감사만 문다, fallback 이 같아 화면은 안 바뀐다)
· 값 지역 반전(`--ink: #ff0000`, 화면 대조만 문다). 셋째는 `[style*=]` 셀렉터로 되돌린
사본이 가짜 0 을 내는 것을 보인다.

### WP2 · `S2` 드리프트 치환기 (건조 실행)

스크래치패드 스크립트다(레포에 안 남긴다 — 일회성이고 정확성은 게이트가 사후에 증명한다).
입력은 `bun scripts/verify-tokens.ts --json` 이 낸 판정 전건이고, 드리프트만 골라
`(file, line, prop, rawValue)` 자리의 리터럴을 `"var(--토큰)"` 으로 바꾼다.

**「토큰 값 ≠ 리터럴 값」이면 그 자리를 거부하고 멈춘다** — 치환기가 값을 고르는 일이 없어야
이 배치가 「화면 변화 0」을 주장할 수 있다.

**완료 기준**: 드리프트 608건이 **전건 매칭**되고 미매칭 0. 파일은 아직 안 고친다.
`expr-literal` 드리프트 3건(`HopJourney.tsx:213` · `RoutingTableLab.tsx:161` ·
`ObserverView.tsx:187`)은 삼항 안이라 따로 확인한다.

### WP3 · `S3` 드리프트 적용 · osi-7-layers + vpn-anatomy

큰 구획 둘(204 + 175 = 379건, 21파일). 커밋은 **시리즈별로 2개** — 글 하나 단위로 되돌릴 수
있게 한다(KAN-072 규약).

**완료 기준**: 두 구획의 드리프트가 0 이고 **위반 건수는 불변**(osi 46 · vpn 47) ·
하네스 대조 차이 0 · `tsc --noEmit` 신규 0.

### WP4 · `S4` 드리프트 적용 · container-anatomy + webrtc + auth-authz + tauri

작은 구획 넷(67 + 78 + 65 + 19 = 229건, 13파일). 커밋 4개.

**완료 기준**: 같은 조건. 배치 종료 시 `bun run tokens:verify` 가 **드리프트 0 · 위반 170**
을 내고, 기준선은 아직 안 갱신한다(배치3 이 한 번에 한다 — 중간에 갱신하면 되돌아가도 안
잡힌다).

## 2. 의존과 순서

`S1 → S2 → (S3 ∥ S4)`. 앞 둘은 진짜 직렬이다 — `S2` 의 건조 실행 결과를 믿으려면 `S1` 이
살아 있어야 하고, `S3`·`S4` 는 `S2` 가 만든 같은 치환기를 돌린다.

`S3`·`S4` 는 파일 집합이 안 겹쳐서 병렬이 된다. 다만 **같은 워크트리에서 찍은 전후 대조는
못 믿는다** — 병렬로 돌리면 상대가 고친 파일이 내 몫으로 잡힌다(KAN-072 실측: 홈 −49px ·
글 목록 −483px 이 남의 변경이었다). 자기 파일만 `HEAD` 로 되돌린 사본을 따로 구워 대조하는
것이 그 답이고 `S1` 하네스가 그것을 한다.

배치 밖 의존: 없다. 기준선 갱신은 배치3.
