## 1. 작업 패키지

### WP1 · `S1` 원본 정규화 규칙 확정

`raws/ddd-transaction-account-discussion.mdx`(93KB, 유일한 실물 표본)를 열어
`graphData` 노드를 전수 분류한다. 축은 둘 — `source`(`USER_EXPLICIT` · `MODEL` ·
`SYSTEM`)와 `type`(`USER_INPUT` · `CONVERSATION_HISTORY` · `EPHEMERAL_MESSAGE` · …).
분류표를 놓고 **버릴 것과 남길 것**을 정한다. 최소한 이것들이 판정 대상이다:

- 시스템 프롬프트 · `EPHEMERAL_MESSAGE` · `USER_SETTINGS_CHANGE` — 버릴 후보
- `tool_calls` 와 그 결과 — 버릴 후보이나, 대담에서 근거로 인용될 수 있어 **요약 보존**을 검토
- `<USER_REQUEST>` 래퍼 태그 · `<ADDITIONAL_METADATA>` 시각 스탬프 — 껍데기만 벗긴다
- 모델의 사고 과정 / 플래너 출력 — 버릴 후보

동시에 **비밀 정보 필터**를 규칙에 넣는다. 이 레포는 공개이고 `raws/` 도 커밋되므로,
경로·토큰·개인정보가 원문에 실려 나가는 경로를 여기서 막는다.

산출물은 `.claude/skills/talk-ingest/assets/NORMALIZE_RULES.md`(스킬 디렉터리는 배치3에서
생기므로, 이 배치에서는 `raws/talks/_rules/NORMALIZE_RULES.md` 에 두고 배치3에서 옮긴다).

**완료 기준**: 규칙 문서가 존재하고, 표본에 규칙을 적용했을 때 **남은 발화 수와 바이트 수의
실측값**이 그 문서에 박혀 있다(예: `노드 N개 → 발화 M개, 93KB → XKB`). 눈대중 금지.

### WP2 · `S2` L1 원문 보존 규격

디렉터리 레이아웃과 출처 메타 스키마를 확정한다.

```
raws/talks/<slug>/
  source/<원본파일>        # 받은 그대로. 확장자 유지. 아무도 안 고친다
  source.json              # 출처·모델·수집일·형식·sha256
  talk.md                  # L2 정형본 (WP3 에서 스키마 확정)
```

`source.json` 후보 필드: `origin`(어느 도구의 export 인가) · `model` · `capturedAt` ·
`format`(어느 어댑터로 읽는가) · `files[]`(경로 + `sha256` + `bytes`) · `slug`.

**완료 기준**: 표본 1건을 실제로 이 구조로 앉히고, `sha256` 을 재계산했을 때
`source.json` 의 기록값과 일치한다.

### WP3 · `S3` L2 정형 스키마 + Zod 파서

`talk.md` 문법을 정의하고 `src/lib/talk/talkSource.ts` 에 Zod 스키마와 파서를 쓴다.
문법은 **최소 마커**로 간다 — 사람이 그냥 마크다운을 쓴다고 느껴야 한다.

목표 구조는 `polssin-daedam` 명세(`.claude/authoring/specs/polssin-daedam/spec.json`)의
`sections` 셋에 1:1로 대응시킨다 — `frontmatter` · `qa`(repeat) · `pullquote`.
`## 마치며` 는 템플릿에 있으므로 선택 항목으로 받는다.

**완료 기준**: 표본 파싱이 성공하고, 아래 5개 위반 케이스가 **각각 서로 다른 에러
메시지**로 실패한다(같은 메시지로 뭉뚱그리면 미완).

1. `<QA>` 번호 불연속 (SP1)

  기운다. 완화: 파이썬으로 `graphData` 를 파싱해 **`(source, type, len(content))` 표만
  뽑아** 보고, 본문은 표본 노드 몇 개만 연다.

  이 배치는 **기존 파일을 고치지 않고 새 파일만 만든다** — revert 충돌 위험이 낮다.
