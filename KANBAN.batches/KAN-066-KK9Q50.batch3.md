## 1. 작업 패키지
<!-- work 하나에 WP 하나. 각 WP 는 완료 기준으로 끝난다. -->
### WP1 · `S6` `talk-ingest` 스킬

`.claude/skills/talk-ingest/` 를 저작한다. 흐름은 넷이다.

1. 원본 투입 → `raws/talks/<slug>/source/` 에 그대로 앉히고 `source.json` 봉인
2. 배치1의 정규화 규칙으로 노이즈 제거 → 발화만 남긴 중간 형태
3. 질문 재구성 + 톤앤매너·비문·맞춤법 교정 — `authoring-kit` 의 `polssin-daedam` spec 과
   `ppangtolab-prof` voice 에 위임한다. **이 스킬이 문체 규칙을 자체 보유하지 않는다**
   (CLAUDE.md: 집필 규칙은 authoring-kit 이 소유)
4. `scripts/build-talk.ts` 호출 → L3 굽기 → `talk:verify`

배치1이 `raws/talks/_rules/NORMALIZE_RULES.md` 에 임시로 둔 규칙 문서를
`.claude/skills/talk-ingest/assets/NORMALIZE_RULES.md` 로 옮긴다.

**완료 기준**: 표본 1건이 원본 투입부터 발행 가능한 MDX 까지 한 흐름에 통과하고,
**L1 원문이 한 바이트도 안 바뀐다**(`talk:verify` 의 해시 검사로 판정).

### WP2 · `S7` 접점 문서화

세 곳을 고친다.

- `CLAUDE.md` 의 「폭신 대담」 절 — 3계층과 `talk-ingest` 진입점을 적는다
- `.claude/skills/init-post/SKILL.md` — `--talk`(빈 스켈레톤)와 `talk-ingest`(원본에서

**완료 기준**: 세 곳 갱신 후 `bun run build` 재통과, `talk:verify` 0.

## 3. 리스크
<!-- 이 배치가 예산을 넘길 지점, 되돌리기 어려운 지점. -->

- **스킬이 문체 규칙을 자체 보유하려는 유혹.** 이 저장소가 이미 한 번 겪은 실패다
  (세 저장소가 같은 규칙을 각자 들고 있다가 갈라짐). 교정은 전부 `authoring-kit` 에
  위임하고 이 스킬은 **매체 결정**만 갖는다.
- **`CLAUDE.md` 는 다른 카드와 겹치는 파일이다.** 「폭신 대담」 절만 만진다.
- **`_shared` 스킬 자산 관례를 확인하지 않았다** — 착수 시 `.claude/skills/_shared/` 를
  먼저 읽고 따른다.
- 유저 레벨(`~/.claude/skills/`)에 동명 스킬이 생기면 프로젝트 개정본이 조용히 가려진다.
  저작 후 중복 여부를 확인한다.
