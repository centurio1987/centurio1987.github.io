## 1. 작업 패키지

### WP1 · `S5` 인식기 둘 — `typeUnitless` + `fontFamilyStr` [기준선 갱신 #1]

**게이트가 굵기·행간·자간·raw 서체를 아예 못 본다.** 못 보는 이유가 갈래마다 다르다.

- **굵기·행간**은 `propAxis.UNITLESS_PROPS` 에 갇혀 있다. 그 표는 원래 `lineHeight: 1.45` 가
  `--text-*` 의 px 스케일과 대조돼 가짜 위반이 되는 것을 막으려고 세운 것인데(KAN-073),
  막는 방식이 **히트를 아예 안 내는 것**이라 지금은 굵기·행간 자리가 통째로 판정 밖이다.
- **CSS 소수 행간**(`line-height: 1.75`)은 옛 `LITERAL` 이 `1`·`75` 로 갈라 세고, 그 동작은
  감사 원자료 3,539 히트 대조의 일부라 **고칠 수 없다.**
- **raw 서체**는 실측으로 찾은 구멍이다 — `font-family` 히트 131건이 **전부** `css-decl`·준수인데
  JSX 의 `fontFamily: "monospace"` 40여 자리는 **히트 0건**이다. 이것이 없으면 `S10`~`S12` 의
  완료 기준(「같은 글 안에서 코드블록과 시뮬 코드가 같은 서체로 뜬다」)을 게이트로 증명할 수 없다.

인식기 둘을 새 갈래로 붙인다. **옛 정규식을 고치지 않는다** — KAN-075 가 실측으로 남긴 규약이다.

- `typeUnitless` — `fontWeight`·`lineHeight` 세 형태(JSX style 객체·표현식 / `.astro` 인라인
  `style` / **CSS 선언의 소수 `line-height`**). `letterSpacing` 은 **관할 밖**이다: JSX
  `letterSpacing` 은 실측 1건뿐이고(`PosterHero.tsx:132`, SVG 속성이라 문자열) 자간 47자리는
  전부 CSS 다. **지금 겹칠 자리가 0 이고 장래 겹침을 미리 가르는 것이다.**
- `fontFamilyStr` — 스타일 값 자리의 **문자열 서체 이름**. `exprValue` 가 문자열을 보지만
  `font-family` 는 `comparable()` 이 이미 판정하는 축이라 갈래가 갈린다.

**함정 하나가 이 work 의 핵심이다.** CSS 소수 파편을 내릴 때 `verdict` 를 건드리면 안 된다 —
`측정 제외` → `판정 불가` 접기는 `color.ts:179` 의 `emit()` 안에만 있고 `docrule` 은 직접 박는데,
`check-recognize-invariant.ts` 의 `keyOf` 가 **`verdict` 를 키에 넣고 `reason` 은 뺀다.**
`verdict` 는 `판정 불가` 그대로 두고 **`auditLabel`·`reason` 만** 바꾼다.

`classify()` 는 **`src === "type-unitless"` 일 때만** 소수를 온전히 무는 분기를 **한 줄** 연다.

**완료 기준**: `fontWeight` 116 · `lineHeight` 71 · raw `fontFamily` 40여 자리가 인식에 들어온다.
고장 픽스처 둘이 선다(무단위 굵기=위반 · CSS 소수 행간이 온전히 인식=판정 불가).
`bun run tokens:invariant -- --before <배치2 착수 직전 스냅샷> --self-test` 가 **옛 히트 증분 0 ·
겹침 0 · 가드 자가검사 통과**. `selfTestFaults` 와 기준선을 **같은 커밋에서** 갱신.

### WP2 · `S6` 토큰 신설 + 판정층 + `fontRoles` 좁히기 [기준선 갱신 #2]

`S3` 이 정한 13개 토큰이 `tokens.css` 에 서고, `docrule.ts` 가 그 셋을 잰다.

`docrule.ts` 를 넓힌다 — **새 모듈을 안 만든다.** `auditLabelOf`·`driftToken`·`Scale` 이 모듈
지역이고, KAN-076 이 `stroke` 를 `color.ts` 에 넣은 선례가 있으며, **두 모듈이 같은 히트를
claim 하면 판정이 둘 내려간다.**

① `--font-weight-*` 3단 · `--font-leading-*` 6단 · `--font-track-*` 4단(전부 `em`)이 선다.
② `docrule` 의 글자 크기 분기 뒤에 3갈래를 붙이고 `notes` 에 세 줄을 낸다(지금은 한 글자도 안 나온다).
③ `baseline.judgeAxis()` 가 사유 접두 셋으로 갈라 **래칫 칸이 셋 는다.**
④ `fontRoles()` 를 `--text-` 접두로 좁힌다.

**④의 함정이 둘이다.** 하나 — 픽스처에 `--text-body: 18px` 을 세우면 `Ok.astro:13` 의
`font-size: 18px` 이 **드리프트**가 되어 자가검사 ①(정상 픽스처는 아무것도 안 걸린다)이 깨진다.
`var(--text-body)` 로 함께 고친다. 둘 — 오염 시도 토큰을 픽스처에 심어 **`font-min` 고장이 계속
잡히는지** 본다. 안 심으면 좁히기가 실제로 무엇을 막는지 아무 검사도 안 본다.

**완료 기준**: `bun run tokens:verify` 의 `notes` 에 굵기·행간·자간 세 줄이 나오고 래칫 칸이 셋 는다.
**`git diff` 가 `src/styles/tokens.css` 밖의 `src/` 를 한 줄도 안 건드린다**(화면 불변).
죽여서 확인 셋 — `fontRoles` 좁히기 되돌리기 → 오염 토큰이 `font-min` 을 죽여 **빨개져야** ·
`judgeAxis` 접두 셋 제거 → 세 축이 `font` 칸으로 합쳐져 **기준선이 안 맞아야** ·
`typeUnitless` 제거(WP1) → `selfTestFaults` 래칫이 **빨개져야**.
드리프트 급증분을 **같은 커밋에서** 기준선에 갱신.

### WP3 · `S7` 폰트 파이프라인 — 굵기를 굽고 자체 호스팅으로 전환 [화면이 바뀌는 work 1/2]

**교체가 아니라 파이프라인 도입이다. 굽기·서브셋·배관·전환이 한 커밋에 든다** — 나누면
「선언은 있는데 파일이 없는」 또는 「파일은 있는데 아무도 안 쓰는」 중간 상태가 생기고,
되돌릴 때 그 중간으로 떨어진다.

① `scripts/build-fonts.ts`(`bun run fonts:build`). `S1` 의 조사 스크립트와 달리 이것은
**산출물을 만드는 도구**라 레포에 남는다. 함정 셋을 주석으로 박고, 셋째(`stroke` 전 원본
winding 정규화)에는 **자가검사**를 붙인다 — 구운 글리프의 면적이 원본보다 커야 한다
(버그 상태 +4%, 정상 +66%). 굽기는 `fontTools` + `skia-pathops` 라 파이썬이 필요하다.
**venv 부트스트랩을 스크립트가 진다** — 스크래치패드의 venv 는 사라지는 자리다.

② 서브셋은 **사이트가 쓰는 글자로** 굽는다(`dist/**/*.html` 에서 고유 글자 수집, 실측 1,243자).
**`astro build` 뒤에 온다.**

③ 자체 호스팅 배관 — `public/fonts/` · `@font-face` · `BaseLayout` 의 preload.
`KAN-059` 규약이 그대로 걸린다: **preload 는 LCP 후보 딱 하나**, 폰트 스타일시트보다 **위**.
Google Fonts `<link>` 에서 Gowun Dodum 을 뺀다(Jua·Gaegu·Space Mono·JetBrains Mono 는 남는다).

④ **선언 다섯 곳을 동시에 맞춘다** — `BaseLayout.astro:88` · `tokens.css:215-219` ·
`render-viz.ts:50-51`(**이미 갈려 있다**) · `blogVizStyleGuide.ts:79-80` ·
`bbangtoTonyStyleGuide.ts:97-98`. `global.css:10-15` 는 그중 **둘만** 짝지어 놨다.

⑤ `--font-mono`·`--font-code` 스택 **끝에 본문 서체를 놓는다**(§7-6). 라틴·숫자는 원래 얼굴이
그대로 그리고 한글만 떨어진다 — 본문 서체가 이미 로드돼 있으므로 **추가 다운로드 0**.

⑥ **`font-synthesis: none` 을 전역에 선언한다.** 지금 선언 0건이라 합성이 막을 것 없이 걸려 있고,
진짜 면이 생긴 뒤에도 안 막으면 없는 단이 조용히 합성으로 메워진다.

**완료 기준**: `bun run build` 종료 0(46쪽). `bun run render:compare` 는 **exit 1 이 정상**이고
판정은 diff 목록으로 한다 — **본문 400 은 한 픽셀도 안 움직이고**(같은 아웃라인이다), 움직이는
것은 굵기가 걸린 자리와 `--font-mono`·`--font-code` 의 한글뿐이며, **자리(`width`/`height`/
`top`/`left`)가 무너진 지면은 0.** `deco:verify`·`viz:verify`·`talk:verify`·`width:verify` 종료 0.

## 4. 착수 시점 판단

**3 work 를 그대로 간다. 다만 `S7` 에 명시적 방아쇠를 둔다.**

`S5`·`S6` 은 뗄 수 없다 — `S6` 의 판정 3갈래는 `S5` 가 들여보낸 히트를 재는 것이고, 둘을 갈라
배치를 끊으면 **「인식은 넓어졌는데 아무도 안 재는」 기준선**이 한 배치 동안 굳는다. 그 상태는
래칫에 「부채가 없다」로 잡혀서, 다음 배치가 그것을 정상으로 읽는다.

`S7` 은 성질이 다르다. 화면이 처음 움직이고 산출물에 바이너리가 들어오며 외부 의존(파이썬 ·
Playwright)이 붙는다. **방아쇠**: 굽기·서브셋·배관·전환 넷을 **한 커밋에 담을 수 없다고 판단되면
쪼개지 말고 배치3 으로 통째로 미룬다.** 배치3 은 `S8`(`type:verify`)·`S9`(데코 재측정)이고,
`S8` 은 `S7` 의 산출을 검사 대상으로 받으므로 셋이 한 배치로 붙어도 순서가 그대로 선다 —
오히려 「만든 것을 그 자리에서 검사한다」가 된다. 미루는 쪽이 손해가 아니라는 것이 이 방아쇠를
둘 수 있는 근거다.

**`S5` 착수 전에 `tokens:invariant` 용 스냅샷을 먼저 뜬다.** 인식층을 넓힌 뒤에는 그 커밋
이전 상태를 다시 뜰 수 없고, 못 뜨면 「옛 히트가 안 움직였다」를 증명할 방법이 이 배치에서 사라진다.
