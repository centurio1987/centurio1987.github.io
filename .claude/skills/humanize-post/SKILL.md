# humanize-post 스킬

집필(`tech-deepdive`)이 끝난 **초고에서 기계 냄새를 빼는** 단계다. 문장 하나하나는 멀쩡한데 스무 문장을
이어 읽으면 AI인 글 — 어미가 돌림노래처럼 반복되고, 쉼표가 문법적으로 가능한 모든 자리에 찍혀 있고,
결론이 어디서 본 공식대로 닫히는 글 — 을 잡는다.

**판정 단위는 문장이 아니라 구간(문단·섹션)이다.** 한 번 나온 건 증상이 아니다. **반복이 증상이다.**

## 워크플로우 상의 위치

```
tech-deepdive(집필)
  → [humanize-post: 스캔 → 등급 → 윤문 → 의미보존 검증]   ← 이 스킬
  → review-post(미시: 맞춤법·번역투)
  → review-writing(거시: 설득·논리·구조·문체)
  → quality-gate(기술)
  → post-finalize → publish-post → ship-post
```

**왜 집필 바로 다음인가.** AI 문체는 초고에 가장 짙고, 뒤 단계로 갈수록 고치는 비용이 커진다. 여기서
어미와 리듬을 손봐 두면 `review-post`는 맞춤법에, `review-writing`은 논리에 집중할 수 있다. 반대로
구조가 확정된 뒤에 리듬을 만지면 앞 단계 판정이 무효가 된다.

`raw-to-draft`로 들어온 글(저자가 처음부터 끝까지 직접 쓴 원고)에는 **이 스킬을 돌리지 않는다.** 사람이
쓴 글에 AI 탐지 규칙을 들이대면 저자 문체만 깎인다.

## 책임 경계 (겹침 방지 — 반드시 지킨다)

| 스킬 | 그 스킬이 잡는 것 | **humanize-post(이 스킬)가 그 영역에서 하지 않는 것** |
| --- | --- | --- |
| **humanize-post (이 스킬)** | AI 기계 리듬 — 쉼표·어미·버즈워드·헤지·상투 구조 | — (이게 내 권한 범위) |
| `review-post` | 맞춤법·조사·**번역투(영어 골격)**·스캔성 + AI 문체 **잔존 판정** | `~을 통해`·이중 피동·무생물 주어를 **고치지 않는다**(발견하면 이관) |
| `review-writing` | 설득·논리 개연성·글 구조·문체 일치 | 문단 이동·섹션 신설·논지 보강을 **하지 않는다** |
| `quality-gate` | 기술 깊이·정확성 | 기술 서술의 사실관계를 **건드리지 않는다** |

번역투는 [`../_shared/NATURAL_KOREAN_GUIDE.md`](../_shared/NATURAL_KOREAN_GUIDE.md) 소관이다. 윤문하다
눈에 띄면 **고치지 말고 보고서 말미에 "review-post로 넘김" 목록에 적는다.**

## 입력 / 출력 계약

- **입력**: 초고 경로(보통 `draft/<…>.mdx`). 없으면 `draft/` → `src/content/posts/`에서 mtime 최신을 골라 한 줄로 알린다.
- **출력**: 자연스러움 등급(윤문 전/후) + 범주별 적발 건수 + 수정률 + 의미 보존 6점 검증 결과 + review-post 이관 목록.
- **수정 권한**: **문장 단위 표현 교정에 한해** `Edit`. 문단 이동·섹션 신설·내용 추가는 권한 밖이다.

## 동작 순서

### 1. 대상 결정과 제외 구간 확정

`Read`로 전체를 읽는다. 아래는 **스캔·윤문 대상에서 제외**한다(이 레포는 마커가 많다 — 실수로 건드리면 빌드가 깨진다).

- frontmatter(`---` 블록), 상단 `import` 문
- 코드 펜스(```` ``` ```` 전체), 인라인 코드(`` ` ``)
- ` ```viz ` · ` ```figure ` 블록, `<<meme: …>>` 마커, `[[[…]]]` 레거시 마커
- JSX 컴포넌트 태그(`<Name client:visible />`)
- 인용문(`>` 블록) 중 **외부 인용** — 원문이므로 고치지 않는다. 저자가 쓴 강조 인용은 대상.
- `draft/` 스캐폴드 잔재(`## 플롯 후보`, `## 선택한 플롯`, `## 주의사항`)

### 2. 정량 스캔

```bash
python3 .claude/skills/humanize-post/scripts/scan_ai_style.py "<대상 파일>"
```

문단별 쉼표 밀도, 같은 어미 연속 횟수, 버즈워드·헤지·문두 접속사 적중, 불릿 비중, 이모지·볼드 개수,
문장 길이 분산을 뽑아 **패턴 코드별 적발 목록**과 **자연스러움 등급**을 출력한다.

스크립트는 **기계적으로 셀 수 있는 것만** 센다. 아래 넷은 판단이 필요해 스크립트가 못 잡으므로, 출력 결과를
받은 뒤 **본문을 직접 읽고 사람 눈으로 채운다.** 스크립트 결과만 믿고 넘어가지 않는다.

- **F1~F4** 상투 구조·마무리 공식 (요약 반복 결론, `살펴보았습니다` 결론, 균질 섹션, 무근거 당위)
- **R4** 3의 법칙 강박 · **R6** 품사 편중 · **R7** 대구 강박

### 3. 판정

[`../_shared/AI_KOREAN_PATTERNS.md`](../_shared/AI_KOREAN_PATTERNS.md) 기준으로 등급을 매긴다.

등급 계산의 단위는 **적발된 패턴 코드 수**다(코드 하나가 몇 번 걸렸든 1개로 센다 — 스캐너 출력과 동일).

| 등급 | 기준 | 처리 |
| --- | --- | --- |
| **A** | S1 코드 0 · S2 코드 ≤2 | 윤문 없이 통과 |
| **B** | S1 코드 0 · S2 코드 3~5 | S2만 선별 교정 후 통과 |
| **C** | S1 코드 1~2 또는 S2 코드 ≥6 | 윤문 필수 |
| **D** | S1 코드 ≥3 | 윤문 필수 + 재스캔 |

**합격선은 B 이상.**

### 4. 저자 색 필터 (윤문 전 반드시 통과)

적발 목록을 그대로 고치기 전에, **`AI_KOREAN_PATTERNS.md` Part B(저자 색 보호 목록 9항목)** 와 대조한다.

- `결론적으로` · 만연체 · 당위 마무리 · 병렬 점층 · 한자어 고전 인용 · 직접 호명 · 격식체 통일 · 의도적 자조 톤
  → **저자 색이다. 적발 목록에서 뺀다.**
- 볼드는 저자 습관이지만 문단당 3개 이상이면 절제 대상(P5).

> **Part A와 Part B에 동시에 걸리면 Part B가 이긴다.** 애매하면 고치지 않는다. 자연스러움을 핑계로
> 저자 목소리를 지우는 것이 이 단계의 가장 큰 실패다.

### 4.5 원본 사본 확보 (7단계 수정률 계산에 필수)

`Edit`로 손대기 **전에** 원본을 스냅샷해 둔다. 이걸 빠뜨리면 7단계 가드를 실행할 수 없다.

```bash
cp "<대상 파일>" "/tmp/humanize-before-$(basename '<대상 파일>')"
```

### 5. 윤문 (우선순위 순)

판별력이 높은 순서로 고친다. 아래 순서를 지켜야 수정률을 아낀다.

1. **S1 전량** — 쉼표 과다(P1), 어미 돌림노래(R1a), 이모지(P3), 버즈워드 W1/W2/W8, 헤지 중첩(H1), 양비론(H4), 문두 접속사 3연속(D1), 요약 반복 결론(F1)
2. **S2 중 빈도 초과분** — 판정선을 넘은 것만. 선 안쪽은 두는 게 낫다
3. **단문 강타 심기(R2)** — 섹션마다 짧게 끊는 문장이 하나도 없으면 하나 만든다(STYLE_GUIDE F2 복원)
4. **S3는 건드리지 않는다** — 다른 신호와 겹칠 때만, 그것도 1·2를 고친 뒤 여전히 남을 때만

**고치는 방식**

- 어미 반복은 **어미만 바꾼다.** 문장을 새로 쓰지 않는다.
- 쉼표 과다는 **문장을 끊거나 어순을 바꾼다.** 절을 삭제하지 않는다.
  - **`와/과`로 이어 붙여 쉼표만 없애지 마라(R8).** `A, B, C, D` → `A와 B와 C와 D` 는 교정이 아니라
    개악이다. 카운터는 내려가고 한국어는 나빠진다. 항목 나열은 **쉼표 그대로 두거나**(P1의 나열
    예외에 걸려 애초에 적발되지 않는다) **가운뎃점(`A·B·C`)** 으로 줄인다.
  - 나열이 길어 정말 거슬리면 **문장을 쪼개는 게 아니라 목록으로 뺀다.**
- 버즈워드는 **구체로 치환하거나 문장째 삭제한다.** 근거를 새로 만들어 채우지 않는다 — 없는 근거가 필요하면 `tech-deepdive`에 되돌린다.
- 불릿 복원(R5)은 **연결어를 붙여 산문으로 잇는 선까지.** 내용을 더하지 않는다.

### 6. 의미 보존 6점 자가검증 (필수 — 건너뛰기 금지)

윤문 후 원문과 대조해 **여섯 가지가 전부 살아 있는지** 확인한다. 하나라도 깨지면 **그 편집을 되돌린다.**

| # | 항목 | 확인 방법 |
| --- | --- | --- |
| 1 | **수치·날짜·고유명사** | 원문의 숫자·버전·제품명·API명이 그대로인가 |
| 2 | **인과 방향** | `A라서 B`가 `B라서 A`로 뒤집히지 않았는가 |
| 3 | **부정** | `~않는다`·`~없다`가 유실되거나 이중부정으로 뒤집히지 않았는가 |
| 4 | **직접 인용** | 인용 부호 안 문장이 한 글자도 안 바뀌었는가 |
| 5 | **핵심 주장** | 각 섹션의 주장이 약화·강화되지 않았는가 (헤지를 뺐다고 없던 확신을 만들지 않았는가) |
| 6 | **격식 수준** | `~합니다` 톤이 유지됐는가. 어미를 섞다가 반말·구어로 미끄러지지 않았는가 |

특히 **5번**을 조심한다. 헤지 제거(H범주)는 원래 조심스러웠던 주장을 단정으로 바꾸기 쉽다. **불확실한 건
불확실하게 남긴다.** 헤지를 뺄 자리는 저자가 실제로 확신하는 대목뿐이다.

### 7. 수정률 가드

변경된 문장 수 ÷ 전체 문장 수로 계산한다. 4.5단계에서 떠 둔 사본과 대조한다:

```bash
python3 .claude/skills/humanize-post/scripts/scan_ai_style.py \
  "/tmp/humanize-before-<파일명>" --diff "<대상 파일>"
```


| 수정률 | 처리 |
| --- | --- |
| **< 30%** | 통과 |
| **30~50%** | 통과하되 보고에 ⚠️ 경고 한 줄. "표현 교정 범위를 넘었을 수 있음 — diff 확인 권장" |
| **> 50%** | **중단.** 윤문본을 적용하지 말고 사용자에게 알린다 |

50%를 넘었다면 그건 윤문이 아니라 재집필이다. 사용자에게 이렇게 묻는다:

> "수정률이 N%로 상한(50%)을 넘었습니다. (a) S1만 고친 보수적 윤문으로 다시 / (b) 이대로 적용 / (c) 중단하고 `tech-deepdive`로 재집필"

### 8. 재판정과 보고

윤문 후 **2단계 스캔을 다시 돌린다.** 등급이 B 이상이면 종료, 아니면 5단계로 한 번 더(**최대 2라운드**).
2라운드로도 B에 못 닿으면 남은 S1 항목과 이유를 그대로 보고한다. **임의 통과 금지.**

```
# AI 문체 윤문: <파일>
등급: C → A   ·   수정률: 18% (문장 41개 중 7개)

## 고친 것
- **[R1a]** 어미 돌림노래 4구간 — `~합니다` 반복을 명사형·의문형으로 분산
  - "…동작합니다. …필요합니다. …가능합니다." → "…동작합니다. …필요하죠. …이게 가능해집니다."
- **[P1]** 쉼표 과다 3문단 — 문단당 평균 2.1개 → 1.1개
- **[W2]** `시사하는 바가 큽니다` 2건 → 구체 서술로 치환

## 저자 색으로 판단해 두고 넘어간 것 (Part B)
- `결론적으로` 2회 — STYLE_GUIDE F3 저자 연결어
- 종속절 3개 만연체 5문장 — F2 저자 호흡

## 의미 보존 6점: ✅ 전부 통과
## review-post로 넘김 (번역투 — 이 스킬 권한 밖)
- `~을 통해` 4회, `~에 대한` 3회

다음: `review-post`
```

호출 맥락:
- **오케스트레이터 안에서**: 등급 B 이상이면 자동 통과하고 `review-post`로 넘긴다. 수정률 50% 초과나 2라운드 후 C·D면 다음 단계를 막고 사용자 판단을 구한다.
- **사용자 직접 호출**: 스캔 결과와 등급을 먼저 보여준 뒤 "(a) 자동 윤문 / (b) 항목 골라 적용 / (c) 진단만 보고 끝"을 묻는다. **(a) 동의 전에는 `Edit`를 호출하지 않는다.**
