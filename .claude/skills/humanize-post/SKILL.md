# humanize-post (AI 문체 윤문 진입점)

> **판정 기준은 이 파일에 없다.** 6범주 패턴·심각도(S1~S3)·자연스러움 등급(A~D)은 플러그인의
> L0 `machine-rhythm` 이 소유한다. 이 파일에는 **고치는 방식**과 **원문을 지키는 가드**만 남는다.

문장 하나하나는 멀쩡한데 스무 문장을 이어 읽으면 AI 인 글을 잡는다. **판정 단위는 문장이 아니라 구간이다 — 한 번 나온 건 증상이 아니고 반복이 증상이다.**

## 0. 사전 확인

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py status && \
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py lock
```

플러그인이 없으면 **여기서 멈춘다.** 구 패턴 카탈로그로 조용히 돌아가지 않는다 — 그러면 어느 기준으로 저자 색을
지웠는지 알 수 없게 된다. 구 자산은 git 이력에만 있고, 복구는 되돌리기지 우회로가 아니다. `lock` 이 stale 이면 기준이 바뀐 것이다.

## 1. 저자 색 보호 — **바뀐 부분이다. 읽고 넘어가라**

보호 목록은 더 이상 한 사람의 문체 문서에서 오지 않는다. **활성 voice 가 말한다.**

| 저자 | voice | 이 스킬에서 |
| --- | --- | --- |
| 빵관 토니 — 사용자 본인(사람) | `ppangto` (`usage: "preserve"`) | **사용자가 직접 쓴 초안을 다듬을 때만** 지킬 색 |
| 빵토랩 연구원·교수님·선생님 (AI) | `ppangtolab-researcher` · `-prof` · `-teacher` | 그 voice 의 `waivers[]`·`axes` 가 보호 목록 |

**`ppangto` 의 색을 AI 퍼소나 글에 적용하지 않는다.** 예전에는 한 저자의 만연체·당위 마무리·`결론적으로` 가 모든 글의
보호 목록이었지만 그건 사용자 본인의 목소리다. AI 퍼소나 글에 그 색을 씌우면 쓰지도 않은 사람의 문체를 흉내 내게 된다.
**어느 색을 지킬지는 frontmatter 의 `author` 가 가리키는 voice 가 정한다.**

> 잡아낸 것 중 활성 voice 의 `waivers[]`·`axes` 선언에 해당하는 게 있으면 **되돌린다.** 애매하면 고치지 않는다 — 자연스러움을 핑계로 저자 목소리를 지우는 것이 이 단계의 가장 큰 실패다.

## 2. 대상과 제외 구간 (이 레포 고유)

인자가 없으면 `draft/` → `src/content/posts/` 에서 mtime 최신을 골라 알린다. `raw-to-draft` 원고는
활성 voice 가 `ppangto` 다. 아래는 **제외**한다 — 마커가 많고, 건드리면 빌드가 깨진다.

- frontmatter, 상단 `import`, `export const …` ESM 데이터 블록
- 코드 펜스·인라인 코드, ` ```viz ` 블록, `<<meme: …>>`, JSX 태그(`<Name client:visible />`)
- 인용문(`>`) 중 **외부 인용** — 원문이므로 고치지 않는다. 저자가 쓴 강조 인용은 대상
- `draft/` 스캐폴드 잔재(`## 플롯 후보`·`## 선택한 플롯`·`## 주의사항`)

## 3. 스캔·등급, 그리고 원본 스냅샷

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/scan_ai_style.py "<파일>" --voice <활성 voice>
cp "<대상 파일>" "/tmp/humanize-before-$(basename '<대상 파일>')"   # 6단계 가드에 필수
```

`--voice` 를 주면 **그 퍼소나가 면제한 코드를 등급에서 뺀다.** 안 주면 목소리가 있는 글일수록 등급이 나빠지는
뒤집힌 판정이 된다. **합격선은 B 이상.** 스크립트는 기계로 셀 수 있는 것만 세므로
**F1~F4(상투 구조) · R4 · R6 · R7** 은 본문을 직접 읽고 채운다. 전체 채점 맥락이 필요하면
`Skill(authoring-kit:authoring-gate) <파일> --spec <spec-id>` 로 넘긴다. **`Edit` 로 손대기 전에 반드시 사본을 떠 둔다.**

## 4. 윤문 — 고치는 방식

**S1 전량 → S2 중 빈도 초과분 → 단문 강타 심기 → S3 는 건드리지 않는다** 순으로 고친다.

- 어미 반복은 **어미만 바꾼다.** 문장을 새로 쓰지 않는다.
- 쉼표 과다는 **문장을 끊거나 어순을 바꾼다.** 절을 삭제하지 않는다. **`와/과`로 이어 붙여 쉼표만
  없애지 마라** — `A, B, C` → `A와 B와 C` 는 개악이다. 카운터는 내려가고 한국어는 나빠진다.
  나열은 쉼표를 두거나 **가운뎃점(`A·B·C`)**, 길면 목록으로 뺀다.
- 버즈워드는 **구체로 치환하거나 문장째 삭제한다**(없는 근거가 필요하면 `tech-deepdive` 로 되돌린다).
  불릿 복원은 **연결어를 붙여 산문으로 잇는 선까지** — 내용을 더하지 않는다.
- **표현 교정만.** 문단 이동·절 신설·논지 보강은 권한 밖(→ `review-writing`/`tech-deepdive`).
  번역투(`~을 통해`·이중 피동·무생물 주어)는 고치지 말고 **"`review-post` 로 넘김" 목록에 적는다.**

## 5. 의미 보존 6점 자가검증 (필수 — 건너뛰기 금지)

**플러그인에 없는 이 스킬 고유 가드다.** 윤문 후 원문과 대조해 여섯이 전부 살아 있는지 확인하고,
하나라도 깨지면 **그 편집을 되돌린다.**

| # | 항목 | 확인 방법 |
| --- | --- | --- |
| 1 | **수치·날짜·고유명사** | 원문의 숫자·버전·제품명·API명이 그대로인가 |
| 2 | **인과 방향** | `A라서 B` 가 `B라서 A` 로 뒤집히지 않았는가 |
| 3 | **부정** | `~않는다`·`~없다` 가 유실되거나 이중부정으로 뒤집히지 않았는가 |
| 4 | **직접 인용** | 인용 부호 안 문장이 한 글자도 안 바뀌었는가 |
| 5 | **핵심 주장** | 각 절의 주장이 약화·강화되지 않았는가 |
| 6 | **격식 수준** | 활성 voice 가 선언한 종결 톤이 유지됐는가 |

특히 **5번.** 헤지 제거는 조심스러운 주장을 단정으로 바꾸기 쉽다. **불확실한 건 불확실하게 남긴다.**

## 6. 수정률 상한 50% (필수 — 이것도 이 스킬 고유 가드다)

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/scan_ai_style.py \
  "/tmp/humanize-before-<파일명>" --diff "<대상 파일>"
```

| 수정률 | 처리 |
| --- | --- |
| **< 30%** | 통과 |
| **30~50%** | 통과하되 보고에 ⚠️ 경고 한 줄 — "표현 교정 범위를 넘었을 수 있음, diff 확인 권장" |
| **> 50%** | **중단.** 윤문본을 적용하지 말고 사용자에게 묻는다 |

50% 를 넘었다면 그건 윤문이 아니라 재집필이다. 이렇게 묻는다 — "수정률이 N% 로 상한(50%)을 넘었습니다. (a) S1만 고친 보수적 윤문으로 다시 / (b) 이대로 적용 / (c) `tech-deepdive` 로 재집필"

## 7. 재판정과 보고

3단계 스캔을 다시 돌린다. B 이상이면 종료, 아니면 4단계로 한 번 더(**최대 2라운드**). **자동 통과 금지** —
2라운드로도 B 에 못 닿으면 남은 S1 항목과 이유를 그대로 보고한다. 보고에 담을 것: 등급(전/후) · 범주별 적발
건수 · **수정률** · **의미 보존 6점 결과** · voice 면제로 둔 것 · `review-post` 이관 목록(번역투).

- **오케스트레이터 안에서**: B 이상이면 `review-post` 로 넘긴다. 수정률 50% 초과나 2라운드 후 C·D 면
  다음 단계를 막고 사용자 판단을 구한다.
- **사용자 직접 호출**: 등급을 먼저 보여준 뒤 "(a) 자동 윤문 / (b) 항목 골라 적용 / (c) 진단만" 을 묻는다.
  **(a) 동의 전에는 `Edit` 를 호출하지 않는다.**
