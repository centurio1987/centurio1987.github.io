# Post Draft 스킬

사용자가 적어둔 아이디어/단서 메모 파일을 읽어, **3가지 플롯 후보**와 **해당 주제에서 잊지 말아야 할 주의사항**을 담은 스캐폴드 파일을 동일 디렉토리에 `<원본파일명>-draft.md` 이름으로 생성한다.

본문 초안 작성은 이 스킬의 범위가 아니다 — 사용자가 플롯을 고른 뒤 별도로 진행한다.

## 동작 순서

### 1. 아이디어 파일 경로 확인

인자로 파일 경로가 전달된 경우 그대로 사용한다. 그렇지 않으면 사용자에게 묻는다:

> "어느 아이디어 파일을 기반으로 draft를 만들까요? (예: `docs/posts/architecture/modeling/2026/컨텐츠 모음.md`)"

경로에 공백이 포함될 수 있으므로 따옴표 처리/이스케이프에 유의한다.

### 2. 아이디어 파일 읽기 및 분석

`Read` 도구로 **파일 전체**를 읽는다. 들여쓰기 bullet형, heading+산문형 등 형식이 다양하므로 끝까지 읽어 다음을 식별한다:

- 글의 추정 주제 (한 줄)
- 한 문장 요약 — 이 글이 결국 무엇을 말하려 하는지
- 핵심 주장 / 하위 논점들
- 사용자가 이미 결론을 내려둔 부분과, 아직 열려 있는 분기점

아이디어가 너무 빈약하면(예: 의미 있는 본문이 5줄 미만) 그 사실을 알리고 사용자에게 보강 여부를 묻는다:

> "이 파일에 단서가 많지 않아 의미 있는 플롯 3개를 구별해 뽑기 어려울 수 있습니다. 그래도 진행할까요, 아니면 메모를 좀 더 채운 뒤 다시 부르시겠어요?"

### 3. 출력 경로 결정

같은 디렉토리에 `<원본 stem>-draft.md`를 만든다.

예: `컨텐츠 모음.md` → `컨텐츠 모음-draft.md`

이미 존재하면 덮어쓰기 전에 사용자에게 확인한다.

### 4. 스캐폴드 생성

`assets/DRAFT_TEMPLATE.md`를 읽어 구조를 베이스로 삼고, 아래 항목들을 채워 `Write`로 저장한다.

**채워야 할 항목:**

- **frontmatter의 `source`**: 입력 아이디어 파일 경로 (가능하면 레포 루트 기준 상대경로)
- **frontmatter의 `generated`**: 오늘 날짜 (`YYYY-MM-DD`)
- **`# [추정 주제 한 줄]`**: 글의 주제를 한 줄로
- **`> [한 문장 요약]`**: 이 글이 결국 무엇을 말하려 하는지
- **Plot A / B / C**: 각 플롯은 서로 *명확히 다른* 서사 구조를 갖도록 한다. 예시 유형 (이 중에서 골라 쓰되, 더 적합한 형태가 있으면 그것을 쓴다):
  - 개념 정립형 — 정의 → 차이 분석 → 사례 → 권장
  - 사례 분석형 — 잘못된 사례 → 문제 → 재설계 → 교훈
  - 의사결정 가이드형 — 분기점들 → 각 분기의 판단 기준 → 결정 트리
  - 반례 중심형 — 통념 → 반례 제시 → 통념이 통하지 않는 조건
  - 진화 과정형 — 초기 설계 → 마주친 문제 → 점진적 개선 단계
  - Q&A형 — 자주 마주치는 질문들 → 각 질문의 답
  - 비교 분석형 — 후보들을 축에 놓고 trade-off 정렬

  각 플롯마다 다음을 적는다:
  - `적합한 독자/상황`
  - `구성 흐름` (번호 매김 3~6단계)
  - `이 플롯의 강점`
  - `주의할 점` (이 플롯을 골랐을 때 빠지기 쉬운 함정)

- **주의사항 / 잊지 말아야 할 점**: 이 *특정 주제*에 한정된 항목만 4~8개. 예를 들어 DDD/Aggregate 주제라면:
  - "Aggregation과 Composition을 섞어 쓰지 마라"
  - "value의 식별성 문제를 빠뜨리면 1:n 정규화 논의가 공허해진다"

  같은 식. "결론을 먼저 써라", "예시를 넣어라" 등 보편 글쓰기 팁은 **적지 않는다**.

- **선택한 플롯** 섹션은 비워둔다 (템플릿의 주석만 남긴다).

### 5. 완료 안내

생성된 경로를 알린 뒤, 다음 단계를 짧게 안내한다:

> "`<경로>` 에 스캐폴드를 생성했습니다.
> 마음에 드는 플롯을 골라 `## 선택한 플롯` 섹션에 적어두시면, 이후 그 흐름으로 본문 초안 작성을 이어갈 수 있습니다."

## 분석 시 지킬 원칙

- **3개 플롯은 겹치지 않게.** 같은 흐름을 단어만 바꿔 변형한 것이면 안 된다. 서사 구조 자체가 달라야 한다.
- **주의사항은 토픽 특화로.** 입력 아이디어에서 실제로 언급되었거나 자연스럽게 따라오는 항목만 적는다. 보편 글쓰기 조언 금지.
- **한국어로 작성.** 기술 용어는 원어 그대로 (DDD, Aggregate, Composition, value 등).
- **아이디어 파일을 끝까지 읽는다.** 앞부분만 보고 플롯을 뽑으면 사용자가 후반부에 적어둔 결론과 어긋날 수 있다.
- **사용자가 이미 결론을 내려둔 지점은 존중한다.** 그 결론을 뒤집는 플롯을 제안하지 말고, 그 결론을 어떻게 풀어낼지를 두고 플롯을 나눈다.

## 참조 파일

- `assets/DRAFT_TEMPLATE.md` — 스캐폴드 파일의 표준 구조
