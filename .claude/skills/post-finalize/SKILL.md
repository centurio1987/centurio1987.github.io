# Post Finalize 스킬

작성 완료된 포스트 마크다운/MDX 파일에 대해 다음을 수행한다.

1. 본문에서 핵심 키워드를 뽑아 frontmatter `tags` 에 머지
2. `<<meme: ...>>` 마커가 남아 있으면 `meme-inserter` 에 위탁
3. 잔존 레거시 마커(`[[[...]]]`·```figure```·`(( ))`) 검사 → 경고
4. 본문에 `## 이 시리즈의 다른 글` 섹션이 남아 있으면 **제거**(아래 참조)

본문을 새로 쓰거나 리뷰하지 않는다. **이미지를 생성하지 않는다**(시각물은 이미 `viz` 엔진이 처리).

## 대상과 경로 규약 (Astro)

- 포스트 본체: `src/content/posts/<slug>.md`/`.mdx` (발행 전이면 `draft/<…>` 도 가능)
- 시리즈 네비게이션은 `PostNav.astro`·`SeriesEpisodes.astro` 가 자동 렌더한다 — 본문에 링크를 넣지 않는다.

## 동작 순서

### 1. 대상 파일 경로 확인

인자가 있으면 사용. 없으면 묻는다:

> "어느 포스트 파일을 사후처리할까요? (예: `src/content/posts/aggregate-rdb.mdx`)"

확장자가 `.md`/`.mdx` 가 아니면 중단. 공백/한글 경로는 따옴표 처리.

### 2. 파일 읽기 + frontmatter 파싱

`Read`로 전체를 읽고 YAML frontmatter 를 추출·분리한다.

- frontmatter가 없으면 빈 객체로 시작.
- `title` 이 없으면 한 번 묻는다.
- `series` 는 없어도 무관(시리즈 섹션만 생략).

### 3. 태그 추출

본문 전체에서 **3~8개** 핵심 키워드를 뽑는다.

- 검색·분류에 쓸 단어 우선, 기술 용어는 원어(DDD, Aggregate, RDB)
- 한국어 개념은 한국어("모델링", "도메인 설계")
- 너무 광범위한 단일어 단독은 피하고 특화 조합("DDD 모델링", "Aggregate 설계")

기존 `tags` 배열이 있으면 머지하고 중복 제거. 없으면 신규 추가.

### 4. 시리즈 섹션 제거 (KAN-042에서 폐지)

**`## 이 시리즈의 다른 글` 섹션은 더 이상 본문에 넣지 않는다.** 삽입 로직은 폐지됐다.

이유: `PostNav.astro`(이전화/다음화)와 `SeriesEpisodes.astro`(지난 에피소드 카드 그리드)가
**모든 글에 시리즈 네비게이션을 자동 렌더**하므로 본문 수동 섹션은 순수한 중복이다.
게다가 수동 목록은 형제 편이 발행될 때마다 손으로 갱신해야 해서 "(작성 예정)" 같은
stale 항목과 404 링크를 남긴다 — 자동 렌더는 그 문제가 원천적으로 없다.

따라서 이 단계에서 할 일은 **삽입이 아니라 청소**다:

1. 본문에 `## 이 시리즈의 다른 글` 헤딩이 있으면 그 헤딩부터 **다음 `##` 헤딩 직전(또는 파일 끝)까지** 제거하고,
   헤딩 앞의 빈 줄도 함께 정리한다.
2. 없으면 아무것도 하지 않는다(정상).
3. `series` frontmatter 자체는 **건드리지 않는다** — 자동 렌더와 `seriesNav.ts` 가 그 값을 쓴다.

> 2026-07-29 기준 발행물 14편(auth-authz 4 · osi-7-layers 6 · webrtc 3 · vpn-anatomy-1)에서
> 일괄 제거해 전체 포스트가 "본문에 수동 시리즈 섹션 없음"으로 통일된 상태다. 되살리지 마라.

### 5. `<<meme: ...>>` 밈 자리표시자 처리 (위탁)

문서에 `<<meme: ...>>` 마커가 남아 있으면 **`meme-inserter` 스킬에 위탁**한다
(실재 인터넷 밈·움짤 검색·다운로드·치환). 정규식이 비충돌이라 다른 마커와 침범하지 않는다.

빠른 확인:
```bash
python3 .claude/skills/meme-inserter/scripts/find_markers.py "<대상 파일>"
```
`0 markers`면 건너뛴다. 있으면 `meme-inserter`를 호출해 처리하고, 결과(성공/실패 개수)를 최종 보고에 합친다.

### 6. 레거시 마커 검사 (경고만)

구조형 시각물은 이제 ```` ```viz``` ```` 블록 → **`make-image`(apply-viz)** 로 구현한다. 다음 **레거시** 마커가 남아 있으면 처리하지 말고 **경고만** 한다(마이그레이션 유예; 자동 실패 아님):

- `[[[...]]]` (구 OpenAI 은유 일러스트) — 이제 `viz`(PosterEditorial/AnnotatedIllustration 등)로 대체
- ```` ```figure``` ```` (구 make-image HTML 템플릿) — 이제 `viz` 블록으로 대체
- `(( ))` (구 mdx-concept-diagram) — 이제 `viz` 블록(Flowchart/ConceptMap 등)으로 대체
- ```` ```viz``` ``` 가 **미처리로 남아 있으면** 집필 단계의 `make-image`(apply-viz) 누락 → 경고

이 스킬은 이미지를 생성하지 않으므로 `OPENAI_API_KEY` 가 필요 없다.

### 7. 본문 이모지 → 두들 마크 (마지막 그물)

집필(`tech-deepdive`)·게이트 보완(`authoring-kit:authoring-gate`)·검토(`review-post`)가 다 새고 남은 이모지를 여기서 잡는다.

```bash
bun scripts/check-post-markers.ts     # 파일·글자별로 갈아 끼울 마크까지 찍어 준다
```

- **뜻이 있는 기호(`❌`·`✅`·`⚠` …)는 지우지 말고 `<Mark name="..." />` 로 치환한다.** MDX 본문에서 import 없이 바로 쓴다. 매핑은 `src/lib/doodleMarks.ts` 의 `EMOJI_TO_MARK`, 마크 51종 카탈로그는 `/design/deco`.
- **매핑에 없으면 삭제한다.** 대응이 없다는 건 그 이모지가 뜻이 아니라 꾸밈이라는 뜻이다.
- **코드블록 안은 절대 건드리지 않는다** — `★`·`✔` 로 그린 ASCII 도식은 인용한 화면이다. 체커도 펜스 안은 세지 않는다.
- **제목에는 마크를 넣지 못한다 — 말로 풀어 쓴다.** 목차(`PostToc`)는 `render()` 의 `headings` 에서 텍스트만 뽑는데 JSX 는 텍스트를 안 남긴다. 제목에 꽂으면 목차가 `자주 틀리는 포인트 ( → 교정)` 처럼 뚫리고 앵커 slug 도 흔들린다. `## 자주 틀리는 포인트 (❌ → 교정)` → `(오해 → 교정)`, `### Kaniko — ⚠ 이제 고르면 안 됩니다` → `⚠` 삭제(문장이 이미 경고를 말한다).
- **볼드 앞머리는 마크를 볼드 밖으로 뺀다.** `**❌ 안티패턴**` → `<Mark name="no" /> **안티패턴**`. 글리프 마크는 이미 굵게 그려지므로 보이는 건 같고, 강조 안에 JSX 를 넣지 않아 파서가 흔들리지 않는다.
- 근거와 판정 기준은 `_shared/AI_KOREAN_PATTERNS.md` 의 **P3 치환 규칙**.

### 8. 저장 + 요약 보고

frontmatter + 본문을 합쳐 원본 경로에 덮어쓴다. 결과를 짧게 보고:

> "사후처리 완료:
> - 태그: `DDD, Aggregate, RDB 스키마, 모델링`
> - 시리즈 섹션: 제거 1건 (또는 '없음')
> - 밈: 1개
> - 레거시 마커: 0 (경고 없음)
> - 본문 이모지: 3건 → 두들 마크 치환 (`❌`×2 → `no`, `⚠`×1 → `warn`)"

## 분석 시 지킬 원칙

- **frontmatter 보존.** 기존 필드 삭제 금지, 신규만 추가/갱신, 키 순서 유지.
- **태그는 본문 기반.** 제목만 보지 말 것.
- **재실행 멱등성.** 시리즈 섹션은 있으면 제거·없으면 무동작, 태그는 중복 없이 머지.
- **MDX 안전.** `.mdx` 글은 상단 `import` 문과 `<Component .../>`(viz·React 시뮬) 블록을 frontmatter처럼 보존하고 절대 깨지 말 것. 태그 추출 시 import 경로·컴포넌트명 같은 코드 토큰은 키워드로 넣지 않는다.
- **이미지 생성 안 함.** 시각물은 `make-image`(apply-viz)가 집필 단계에서 이미 구현했다.
