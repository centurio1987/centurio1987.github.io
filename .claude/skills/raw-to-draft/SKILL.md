# Raw to Draft 스킬

`raws/` 에 **이미 다 써 둔 글**을 받아, **내용을 건드리지 않고** 다음만 수행해 `draft/` 로 옮긴다.

1. **맞춤법·띄어쓰기·문장부호 표면 교정** (뜻·문장·목소리는 그대로)
2. **post 형식화** — Astro 스키마 frontmatter 정의 + 문서 위생(문단 사이 빈 줄 등)
3. **밈 삽입** — 본문에 `<<meme: 힌트>>` 마커가 있으면 `meme-inserter` 에 위탁해 실제 밈으로 치환

집필·재구성·논지 보강은 **하지 않는다.** 그건 `post-draft`(플롯 잡기)·`tech-deepdive`(집필) 소관이다.

## 이 스킬이 전제하는 것 — post-draft 와의 차이

| | 입력 상태 | 하는 일 |
|---|---|---|
| **post-draft** | raws가 **아이디어 조각/단서** | 플롯 3개 + 주의사항 스캐폴드 생성 (본문은 사용자가 이후 작성) |
| **raw-to-draft (이 스킬)** | raws가 **이미 완성된 본문** | 맞춤법 교정 + frontmatter + 밈 삽입 → 발행 직전 상태 |

즉 이 스킬은 "쓸 내용을 만드는" 스킬이 아니라 "다 쓴 글을 형식만 입혀 넘기는" 스킬이다. 입력이 5줄짜리 메모거나 bullet 나열이면 잘못 고른 것이니 `post-draft` 를 권한다.

## 워크플로우 상의 위치

```
raws/<완성 원고>.md    (사용자가 처음부터 끝까지 씀)
  → [raw-to-draft]     draft/<원고>-draft.md   (맞춤법 교정 + frontmatter + 밈)
  → (선택) review-post  4축 검토
  → publish-post        src/content/posts/<slug>.md 발행
  → (선택) post-finalize 태그·시리즈·밈
```

밈(`<<meme:>>`)은 이 단계에서 채우고, 구조형 시각물(```viz```)은 손대지 않고 남겨 `make-image`(viz 엔진)가 처리하게 둔다(이 스킬은 이미지를 생성하지 않고 `OPENAI_API_KEY` 도 요구하지 않는다).

## 동작 순서

### 1. 대상 파일 경로 확인

인자가 있으면 사용. 없으면 `raws/` 하위(발행·봉인된 `raws/committed/` 제외)에서 후보를 제시하거나 묻는다:

> "어느 완성 원고를 형식화할까요? (예: `raws/aside: 드디어 arc를 벗어나나.md`)"

경로에 공백·한글·콜론(`:`)이 들어갈 수 있으므로 항상 따옴표 처리한다.

### 2. 원고 읽기 + 상태 판정

`Read` 로 **전체**를 읽는다. 그리고 이 글이 정말 "완성된 본문"인지 먼저 판정한다:

- 문단으로 이어지는 실제 본문이 있는가(단순 bullet 나열/한두 줄 메모가 아닌가).
- 아니라면 멈추고 알린다: "이 글은 아직 조각/단서로 보입니다. 플롯부터 잡으려면 `post-draft` 를 쓰는 게 맞습니다. 그래도 형식화만 진행할까요?"

기존 frontmatter가 있으면 파싱해 두고(값 재사용), 없으면 4단계에서 새로 만든다.

### 3. 맞춤법·표면 교정 (내용 불변)

이 스킬의 핵심 제약: **뜻·문장·목소리를 바꾸지 않는다.** 아래 **표면 오류만** 고친다.

**고친다 (기계적 교정):**
- 한국어 띄어쓰기 (예: "완료 할" → "완료할", "볼일" 유지 등)
- 조사 오류 (은/는, 이/가, 을/를), 중복·잘못된 어미
- 명백한 오타·자모 오류 (예: "추례한" → "추레한", "즐찾한" 은 신조어이므로 유지)
- 문장부호: 괄호·따옴표 짝, 마침표 누락, 연속 마침표, 말줄임표(`...` → `…` 는 선택)
- 영문 기술 용어 대소문자 일관성 (arc → Arc, ai → AI, ux → UX, ui → UI — **단, 글 전체에서 일관되게, 저자가 의도적으로 소문자로 통일했다면 존중**)

**고치지 않는다 (내용·문체 영역 — 손대면 규칙 위반):**
- 문장 재작성·어순 변경·문장 합치기/쪼개기
- 문단 추가·삭제·이동, 섹션 헤딩 신설
- 어휘 교체(뜻이 같아도), 구어체·비속어·말버릇(예: "뭐 다시 본론으로", "십 몇년") 정리
- 저자의 톤·리듬·강조 (번역투로 보여도 저자 문체면 그대로)
- 논지 보강·근거 추가·예시 삽입

**적용 방식:**
- 명백한 기계적 오류(띄어쓰기·조사·오타·부호)는 교정하고, **무엇을 어떻게 고쳤는지 목록으로 보고**한다.
- 판단이 갈리는 것(신조어인지 오타인지, 소문자 통일이 의도인지)은 **고치지 말고** 🟡 로 따로 물어본다.
- 애매하면 고치지 않는다. "내용 불변"이 우선이다.

### 4. frontmatter 정의 (Astro 스키마)

`src/content.config.ts` 스키마에 맞춰 채운다. 발행 직전 상태로 만들되 `draft: true` 를 둔다(아직 `draft/` 에 있으므로).

```yaml
---
title: <제목>                 # 필수. 없으면 원고 첫머리/파일명에서 도출해 사용자 확인
description: <한 줄 요약>       # 권장. 본문에서 한 줄로 요약(새 주장 만들지 말 것)
pubDate: <YYYY-MM-DD>         # 필수. 기본은 오늘 날짜, 사용자 확인
category: <슬러그>             # 필수. 아래 목록 중 하나 (불확실하면 추정 후 한 번 확인)
tags: [..]                    # 선택. 본문 기반 3~8개(확신 없으면 비워 두고 post-finalize에 맡김)
series: <시리즈명>             # 선택. 원고에 시리즈 성격이 명시된 경우만
order: <숫자>                  # 선택 (시리즈 정렬용)
draft: true                   # draft/ 단계이므로 true
---
```

- **제목**: 본문에 명시된 제목이 없으면 파일명(예: `aside: 드디어 arc를 벗어나나`)이나 도입부에서 자연스러운 제목을 **도출**해 사용자에게 한 번 확인받는다. 본문에 H1(`# `)을 새로 심지 않는다 — 제목은 레이아웃이 frontmatter로 렌더한다.
- **category**: 아래 슬러그 중 하나. 스키마 enum에 없는 값은 절대 쓰지 않는다. 불확실하면 추정값을 제시하고 확인한다.
- **기존 frontmatter 보존**: 이미 있던 필드는 지우지 말고 재사용/보완만.

**카테고리 슬러그**: `planning`(기획) · `architecture`(아키텍처) · `strategy`(전략) · `skills`(기술) · `design`(설계) · `research`(리서치) · `quality`(품질) · `leadership`(리더십). `src/content.config.ts` enum·`src/lib/categories.ts` 와 일치해야 한다.

### 5. 밈 삽입 (`<<meme:>>` → meme-inserter 위탁)

문서에 `<<meme: 힌트>>` 마커가 남아 있으면 `meme-inserter` 스킬에 위탁한다. 먼저 존재 여부만 빠르게 확인:

```bash
python3 .claude/skills/meme-inserter/scripts/find_markers.py "<대상 파일>"
```

- `0 markers` 면 건너뛴다.
- 있으면 `meme-inserter` 를 호출해 실제 밈으로 치환하고, 결과(성공/실패 개수)를 최종 보고에 합친다.
- 이 스킬 자체는 밈을 검색·생성하지 않는다 — 위탁만 한다.

> **밈 저장 경로**는 발행 후 slug 기준(`public/images/<slug>/memes/`)이다. draft 단계에서 slug가 확정 전이면, meme-inserter 위탁은 **발행 후**로 미뤄도 된다(마커를 그대로 보존). 원고에 이미 slug가 정해졌거나 사용자가 지금 채우길 원하면 이 단계에서 처리한다.

### 6. 다른 마커는 보존

- ` ```viz``` ` (구조형 시각물·hero) → **손대지 않는다.** `make-image`(viz 엔진, bbangto-ui-visualization) 담당.
- `<Name client:visible />` (인터랙티브 시뮬) → 손대지 않는다. `react-sim` 담당.
- 레거시 마커(`[[[...]]]`·`(( ))`·```figure```)가 있으면 손대지 않되, 새로 만들지 말 것 — 은퇴했다(모두 ```viz```로).

정규식이 서로 겹치지 않으므로 한 문서에 섞여 있어도 안전하다.

### 7. 출력 저장

`draft/<원본 stem>-draft.md` 로 저장한다(원본이 MDX면 `.mdx`). 예: `raws/aside: 드디어 arc를 벗어나나.md` → `draft/aside: 드디어 arc를 벗어나나-draft.md`.

- 이미 존재하면 덮어쓰기 전에 확인한다.
- 필요 시 `draft/` 디렉터리를 만든다.
- **원본 `raws/` 파일은 지우지 않는다.** (봉인은 발행 후 `seal-raws` 담당.)

### 8. 완료 보고

짧게 요약한다:

> "형식화 완료 → `draft/<…>-draft.md`
> - 맞춤법 교정: 12건 (띄어쓰기 7 / 조사 3 / 오타 2) — 아래 목록
> - frontmatter: title·pubDate·category(`skills`)·draft:true 설정, tags 4개
> - 밈: `<<meme:>>` 3개 삽입 (성공 3) / 또는 '마커 없음'
> - 보존: `[[[...]]]` 1개(post-finalize 예정), 본문 내용·구조 불변
> 다음: `review-post` 로 검토하거나 `publish-post` 로 발행"

교정 목록은 `원문 → 수정` 형태로 나열해 사용자가 한눈에 검수할 수 있게 한다.

## 지킬 원칙

- **내용 불변이 최우선.** 뜻·문장·문단·구조·톤을 바꾸지 않는다. 애매하면 고치지 않는다.
- **표면 교정만.** 띄어쓰기·조사·오타·부호·용어 대소문자 일관성까지. 재작성은 금지.
- **교정은 투명하게.** 무엇을 고쳤는지 전부 목록으로 보고. 저자가 되돌릴 수 있게.
- **판단성 항목은 물어본다.** 신조어/의도적 소문자/구어체는 저자 것으로 보고 임의 수정 금지.
- **frontmatter 스키마 준수.** `category` enum, `pubDate` 날짜, `draft: true`. 새 카테고리 창작 금지.
- **본문에 H1 신설 금지.** 제목은 frontmatter로만.
- **마커 경계 존중.** `<<meme:>>` 만 (위탁으로) 채우고 ```viz```(및 잔존 레거시 마커)는 그대로 둔다.
- **원본 raws 삭제 금지.** 이 스킬은 복사·형식화만. 봉인은 `seal-raws`.
- **MDX 안전.** `.mdx` 면 상단 `import`·`<Component />` 블록을 frontmatter처럼 보존하고 깨지 않는다.

## 참조 파일

- `/src/content.config.ts` — 콘텐츠 컬렉션 스키마(필드·enum)
- `/src/lib/categories.ts` — 카테고리 슬러그·라벨·색
- `.claude/skills/meme-inserter/scripts/find_markers.py` — `<<meme:>>` 마커 감지

## 관련 스킬

- `post-draft` — raws가 **조각/단서**일 때 플롯 스캐폴드 생성(이 스킬과 반대 입구)
- `review-post` — 형식화 후 4축(맞춤법/개연성/테크니컬 라이팅/몰입도) 검토
- `publish-post` — draft → `src/content/posts/` 정식 발행(`draft:false`)
- `post-finalize` — 발행물 태그·시리즈 링크·밈(이미지 생성 없음)
- `make-image` — ```viz``` 구조형 시각물·hero(bbangto-ui-visualization)
- `meme-inserter` — `<<meme:>>` 실제 밈 삽입(이 스킬이 위탁)
- `seal-raws` — 처리 끝난 raws 원본을 `raws/committed/` 로 봉인
