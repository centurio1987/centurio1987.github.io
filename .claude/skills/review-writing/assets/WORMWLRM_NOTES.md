- 톤: 공식/내밀/자조 3톤 의도적 혼합으로 딱딱함 완화.

- **배울 점**: (a) 점수/등급 등 시각 기호로 스캔성↑, (b) 타임라인으로 인과 제시, (c) 톤 변화 운영, (d) 내부 링크로 연속성, (e) 구체→추상→구체 마무리.

- **배울 점**: (a) 경험담+상반 결과 오프닝, (b) **시각자료 우선 제시** 후 개념 설명, (c) 비교표·계층 구조로 가독성, (d) 문제→원인→해결 흐름, (e) 실제 적용 사례 + 미래 기술 병행.

## 3. iOS scrollTo/getBoundingClientRect 버그 — 디버깅·트러블슈팅 글

- URL: https://wormwlrm.github.io/2025/11/29/iOS-ScrollTo-GetClientBoundingRect-Bug.html
- 도입: 사용자 관점 증상("화면을 뚫고 나간다") → 개발자 관점 전환, 플랫폼 특이성(iOS) 강조.
- 서사: 기존 해결책 재확인 → 코드 추적 → "뭔가 이상한 걸 발견" → 음수 스크롤 값 원인 규명. 비선형 발견 과정 재현.
- 장치: 스크린샷·데모 코드로 **재현 가능한 증거**, PC vs iOS 비교, 스펙 인용, "??" 감정 표현으로 몰입.
- 깊이: React useRef 예제, scroll 스펙 인용, WebKit 버그 트래커 참조, 수치 증명("top 5098px").
- 마무리: 2가지 해결책(setTimeout vs min/max 절삭) 비교 + "방법 2가 더 안정적" 권장 + 공감("프론트엔드 개발자의 숙명").
- **배울 점**: (a) 구체 증상→근본 원인 추적 서사, (b) 재현 가능한 증거(코드·스크린샷·수치), (c) "왜?"의 반복적 심화, (d) 실무적 대안 비교 + 판단 근거, (e) 감정적 공감 + 실질적 가치로 마무리.

## 체크리스트 반영 요약 (공통 교훈)

1. **시각자료/증거 우선** — 개념 설명 전에 현상·증거를 먼저 보여 학습 효율↑. → CHECKLIST 구조·몰입 항목.
2. **문제→원인→해결(또는 "왜"의 심화)** 흐름 — 각 섹션이 앞 의문을 푼다. → 글 구조 항목.
3. **재현 가능한 근거** — 코드·수치·스펙·표. → 개연성·설득력 항목.
4. **실무적 대안 비교 + 권장** — 트레이드오프와 판단 근거. → 설득력 항목.
5. **구체→추상→구체 + 감정 공감 마무리**. → 마무리·몰입 항목.
