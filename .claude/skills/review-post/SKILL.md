# review-post (미시 검토 진입점)

> **판정 기준은 이 파일에 없다.** 맞춤법·번역투는 플러그인 L0 `grammar`(자연스러운 한국어)가,
> AI 문체 잔존은 L0 `machine-rhythm` 이, 독자 이해·정확성은 L0 `QUALITY_RUBRIC` 이 소유한다.
> 이 파일에는 **어느 렌즈로 볼 것인가**와 **지적 포맷**만 남는다.

검토는 Claude 가 직접 수행한다. 외부 모델(ChatGPT/Gemini) 호출은 하지 않는다 —
외부 검토는 `authoring-write` 가 앞 단계에서 돌린다.

## 0. 사전 확인

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py status
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py lock
```

- 플러그인이 없으면 **여기서 멈춘다.** 구 체크리스트로 조용히 돌아가지 않는다 — 그러면 어떤
  기준으로 지적했는지 알 수 없게 된다. 구 자산은 git 이력에만 있고, 복구는 되돌리기지 우회로가 아니다.

**그리고 강조가 실제로 렌더되는지 기계로 먼저 확인한다.** 눈으로 원문을 읽으면 `**창(window)**이`
는 멀쩡해 보이는데, 화면에는 별표가 그대로 나온다 — 한국어는 조사가 닫는 `**` 에 곧바로 붙고,
CommonMark 는 닫는 자리 **앞이 문장부호이면 뒤가 공백이나 문장부호일 때만** 강조를 닫기 때문이다.

```bash
bun scripts/check-emphasis.ts <파일>     # 경로 생략 시 src/content/posts/ 전체
```

- 비0으로 끝나면 그 자리를 **🔴 [테크니컬 라이팅]** 으로 올린다. 저자 의도(어디까지 굵게 할지)가
  걸려 있으므로 임의로 고치지 않고 지적으로 낸다.
- 표준 수리는 셋이다 — `**용어(term)**조사` → `**용어**(term)조사`, `**"인용"**조사` →
  `"**인용**"조사`, `` **`코드`**조사 `` → `` **`코드`조사** ``.
- **빌드 산출물이 있으면 `--dist` 로 한 번 더 본다.** 렌더된 HTML 을 직접 훑는 쪽이 정본이다.
- `lock` 이 stale 이면 기준이 바뀐 것이다.

## 1. 대상 파일 결정

- 사용자가 경로를 명시했으면 그것을 사용. 아니면 `draft/` → `src/content/posts/` 하위에서
  mtime 최신 `.md`/`.mdx` 를 자동 선택하고 선택한 경로를 한 줄로 알린다. 후보가 모호하면 묻는다.
- `Read` 로 전체 본문을 가져온다. frontmatter 는 본문 검토 대상에서 제외한다 — 명백한 오류
  (필수 필드 누락, 잘못된 yaml)만 결과 끝에 한 줄로 표기한다. `author` 가 비어 있으면 반드시 적는다.
- `draft/` 스캐폴드 잔재(`## 플롯 후보`, `## 선택한 플롯`, `## 주의사항`)는 본문이 아니므로 제외한다.
- spec 을 고른다(`tech-deepdive` / `polssin-daedam`). frontmatter 의 `author` 가 활성 voice 다.

## 2. 채점을 넘기고, 5축 렌즈로 읽는다

```
Skill(authoring-kit:authoring-gate) <파일> --spec <spec-id>
```

게이트가 항목별 판정과 인용 근거를 낸다. 이 스킬은 그 결과를 **아래 5축으로 재배열**하고,
게이트가 기계로 못 세는 문장 단위 지적을 본문을 읽어 채운다.

| 축 | 무엇을 보나 | 기준 소유 |
| --- | --- | --- |
| **맞춤법·문법** | 띄어쓰기, 조사(은/는·이/가·을/를), 중복 어미, 문장부호 짝, 외래어·영문 기술 용어 표기 일관(GraphQL·PostgreSQL), **번역투**(`~에 대하여`·`~을 통해`·이중 피동·무생물 주어) | L0 `grammar` |
| **개연성·논리** | 주장–근거 비약, 미정의 개념 선등장, 앞뒤 모순, 근거 없는 단정(`모두`·`항상`·`절대`), 예시가 주장을 실제로 뒷받침하는가 | L0 `A1·A3·E1` |
| **테크니컬 라이팅** | 한 문장 한 주장, 능동태 우선, 평행 구조, 표제만 훑어도 흐름 파악(scannability), 독자 수준 대비 전문어, 코드·도식이 문맥 없이 먼저 나오지 않는가, 약어 첫 등장 시 풀어쓰기 | L0 `A2·F1` |
| **몰입도** | 도입 훅, 문단 호흡과 정보 밀도, 구체 예시 배치, 끝맺음이 핵심을 다시 짚는가, 같은 말의 다른 표현 반복 | L0 `A4·F2·C7` |
| **AI 문체 잔존** | 게이트 보완이 걷어내지 못하고 남은 기계 리듬 | L0 `machine-rhythm` |

**AI 문체 축은 스캐너 등급을 그대로 인용한다.**

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/scan_ai_style.py "<파일>" --voice <활성 voice>
```

- 등급 **A·B 면 이 축은 "특별히 없음"**, **C·D 면 🔴** 로 올린다.
- 스캐너가 못 잡는 **F1~F4(상투 구조) · R4 · R6 · R7** 은 본문을 직접 읽고 채운다.
- **번역투는 이 축이 아니라 맞춤법 축에서 다룬다.** 중복 지적 금지.
- **활성 voice 가 선언한 색(`axes`·`waivers[]`)은 지적하지 않는다.** 어느 색을 지킬지는
  frontmatter 의 `author` 가 가리키는 voice 가 말한다 — `ppangto`(사용자 본인, `usage: preserve`)
  의 색을 AI 퍼소나(`ppangtolab-*`) 글에 적용하지 않는다.

## 3. 결과 출력

```
# 검토: <파일 경로>
AI 문체 등급: B (S1 0 · S2 3)   ← 스캐너 출력 그대로 (활성 voice 면제 반영)

## 🔴 반드시 수정
- **[축]** 인용: "원문 일부"
  - 문제: <한 줄 진단>
  - 제안: "수정안" (또는 방향만)

## 🟡 검토 권장
- **[축]** 인용: "…" — <지적> / 제안: "…"

## 🟢 잘 된 점 (축별 1줄 이내)
- 맞춤법 / 개연성 / 테크니컬 라이팅 / 몰입도 / AI 문체

## 다음 단계
(a) 직접 수정 / (b) 특정 축만 더 깊게 / (c) 그대로 두기
```

- **인용은 원문 그대로.** 길면 `…` 로 축약. 인용 못 하는 지적은 내지 않는다 — 추측은 지적이 아니다.
- 🔴 는 명백한 오류, 🟡 는 판단성 지적. 모호하면 🟡.
- 같은 패턴 반복은 첫 사례만 인용하고 "유사 사례 N건" 으로 묶는다.

## 4. 후속 처리

- **(a)**: 합의한 항목만 `Edit` 로 수정한다. 항목별로 확인받는다.
- **(b)**: 지정 축만 재검토. **(c)**: 변경 없이 종료.

## 주의

- **사용자가 (a) 에 동의한 항목만 수정한다. 그 전엔 어떤 `Edit`/`Write` 도 호출하지 않는다.**
  이 스킬은 게이트가 아니라 검토다 — 보완 루프를 스스로 돌리지 않는다.
- **AI 문체 축은 판정 전용이다.** (a) 에 동의하더라도 이 축의 지적은 **직접 고치지 않고
  `authoring-kit:authoring-gate` 로 되돌린다.** 그 보완 루프에는 **수정률 상한(50%)과 의미 보존
  6점 자가검증**이 따라붙는데 이 스킬에는 그 가드가 없다. 등급 C·D 면 "게이트 보완 권장" 을 명시한다.
- **5축 밖의 거시 피드백**(주제 변경·글 분리·구조 재배치)은 묻기 전엔 보태지 않는다 → `review-writing`.
- 기술 사실 검증과 **발행 여부 판정은 `quality-gate`** 소관이다.
- 판정 기준을 이 파일에 다시 쓰지 않는다. 바꾸려면 L0 나 spec 을 고친다.
