# review-post

작성된 마크다운 글 한 편을 5가지 축으로 자기검토하고, 일관된 포맷으로 결과를 보여준다. 사용자 승인 전에는 어떤 파일도 수정하지 않는다.

검토는 Claude가 직접 수행한다. 외부 모델(ChatGPT/Gemini) 호출은 하지 않는다.

## 절차

1. **대상 파일 결정**
   - 사용자가 경로를 명시했으면 그것을 사용.
   - 아니면 `draft/` 와 `src/content/posts/` 하위에서 mtime 기준 가장 최신 `.md`를 자동 선택하고, 선택한 경로를 한 줄로 알린다 (예: `최근 수정된 글 사용: draft/foo-draft.md`). 작성 중 글은 보통 `draft/`에 있다.
   - 후보가 모호하면 어느 파일을 검토할지 묻는다.

2. **글 읽기**
   - `Read`로 전체 본문을 가져온다.
   - 상단 frontmatter(`---` 블록)는 본문 검토 대상에서 제외한다. frontmatter 자체에 명백한 오류(필수 필드 누락, 잘못된 yaml)가 있으면 결과 끝에 한 줄로만 표기.
   - `draft/` 의 스캐폴드 섹션(`## 플롯 후보`, `## 선택한 플롯`, `## 주의사항`)은 본문이 아니므로 검토에서 제외한다.

3. **5축 검토 수행 (체크리스트)**

   한 번의 패스로 아래 5축 전부를 평가한다. **5축(AI 문체)은 먼저 스캐너를 돌리고 시작한다:**

   ```bash
   python3 .claude/skills/humanize-post/scripts/scan_ai_style.py "<대상 파일>"
   ```

   ### 맞춤법/문법
   - 한국어 띄어쓰기, 조사 오류(은/는, 이/가, 을/를), 중복 어미
   - 외래어 표기와 영문 기술 용어 대소문자 일관성 (GraphQL, RDB, DDD, PostgreSQL)
   - 문장부호: 괄호/따옴표 짝, 마침표 누락, 연속 마침표
   - 어색한 번역투(피동 남용, "~에 대하여", "~을(를) 통해")

   ### 개연성/논리
   - 주장-근거 연결이 비약 없이 이어지는가
   - 정의되지 않은 개념이 사전 설명 없이 등장하는가
   - 앞뒤 모순
   - 근거 없는 일반화/단정("모두", "항상", "절대")
   - 예시가 주장을 실제로 뒷받침하는가

   ### 테크니컬 라이팅 기준
   - 한 문장 한 주장 / 능동태 우선 / 불필요한 수식어 제거
   - 평행 구조(목록·표제 형태 일관)
   - 표제만 훑어도 흐름 파악 가능(scannability)
   - 독자 수준 대비 전문어 과부족
   - 코드/다이어그램이 문맥 없이 먼저 등장하지 않는가
   - 약어 첫 등장 시 풀어쓰기 ("DDD(Domain-Driven Design)")

   ### 몰입도
   - 도입부 훅: 첫 1–2문단이 "왜 읽어야 하는지"를 주는가
   - 호흡: 단락이 너무 길거나 정보 밀도가 단조롭지 않은가
   - 구체 예시가 적절히 끼어드는가
   - 끝맺음이 핵심을 다시 짚는가
   - 같은 말이 다른 표현으로 반복되는가

   ### AI 문체 잔존

   앞 단계 `humanize-post`가 걷어내지 못하고 **남은 기계 리듬**을 판정한다. 기준은
   [`../_shared/AI_KOREAN_PATTERNS.md`](../_shared/AI_KOREAN_PATTERNS.md) Part A(6범주)이고,
   스캐너 출력(등급 A~D)을 그대로 인용한다.

   - **P — 문장부호**: 쉼표 과다(문장당 3개 이상 / 문단 평균 1.5 초과), 본문 이모지(**뜻이 있으면 삭제가 아니라 `<Mark>` 로 치환** — P3 치환 규칙), 문단당 볼드 3개 이상
   - **R — 리듬**: 똑같은 종결 어절 3연속(R1a), 종결형 4연속으로 단문 강타가 없는 구간(R1b), 문장 길이 평준화, 불릿이 본문의 1/3 초과
   - **W — 버즈워드**: `중요한 역할 / 시사하는 바 / 살펴보겠습니다 / ~에 있어서 / 라고 할 수 있`
   - **H — 헤지**: 한 문장에 완충어 2개 이상, `물론 ~지만 ~역시` 양비론 마무리
   - **D — 담화표지**: `하지만·또한·따라서` 문두 3연속, `기본적으로/사실상`, 산문 속 `첫째/둘째`
   - **F — 상투 구조**: 결론이 본문 표제 되읊기, `이 글에서는 ~을 살펴보았습니다`, 모든 섹션이 같은 3박자

   **판정 규칙**

   - 스캐너 등급이 **A·B면 이 축은 "특별히 없음"** 으로 넘어간다. **C·D면 🔴** 로 올린다.
   - **번역투(`~을 통해`·이중 피동·무생물 주어)는 이 축이 아니라 맞춤법/문법 축**에서 다룬다. 중복 지적 금지.
   - 스캐너가 못 잡는 **F1~F4(상투 구조·마무리 공식)·R4(3의 법칙)·R6(품사 편중)·R7(대구 강박)** 은 본문을 직접 읽고 채운다.

   > **저자 색 보호 (반드시 대조)** — `AI_KOREAN_PATTERNS.md` **Part B 9항목**에 걸리는 것은
   > 지적하지 않는다: `결론적으로`·만연체·당위 마무리·병렬 점층·한자어 고전 인용·독자 직접 호명·
   > 격식체 통일·의도적 자조 톤·(문단당 2개 이하의) 볼드. **Part A와 동시에 걸리면 Part B가 이긴다.**

4. **결과 출력**

   ```
   # 검토: <파일 경로>
   AI 문체 등급: B (S1 0 · S2 3)   ← 스캐너 출력 그대로

   ## 🔴 반드시 수정
   - **[축]** 인용: "원문 일부"
     - 문제: <한 줄 진단>
     - 제안: "수정안" (또는 방향만)

   ## 🟡 검토 권장
   - **[축]** 인용: "..." — <지적> / 제안: "..."

   ## 🟢 잘 된 점 (축별 1줄 이내)
   - 맞춤법: ...
   - 개연성: ...
   - 테크니컬 라이팅: ...
   - 몰입도: ...
   - AI 문체: ...

   ## 다음 단계
   (a) 직접 수정 / (b) 특정 축만 더 깊게 / (c) 그대로 두기
   ```

   - 인용은 원문 그대로. 길면 `…`로 축약.
   - 🔴는 명백한 오류, 🟡는 판단성 지적. 모호하면 🟡.
   - 🟢는 축당 한 줄 이내. 지적할 게 없는 축은 "특별히 없음".

5. **후속 안내**

   > "(a) 지적한 부분 직접 수정 / (b) 특정 축만 더 깊게 보기 / (c) 그대로 두기"

   - (a): 합의한 항목만 `Edit`로 수정. 항목별 확인.
   - (b): 지정 축만 재검토.
   - (c): 변경 없이 종료.

## 주의

- 사용자가 (a)에 동의한 항목만 수정한다. 그 전엔 어떤 `Edit`/`Write`도 호출하지 않는다.
- 5축 밖의 거시 피드백(주제 변경, 글 분리)은 묻기 전엔 보태지 않는다.
- **AI 문체 축은 판정 전용이다.** (a)에 동의하더라도 이 축의 지적은 **직접 고치지 않고 `humanize-post`로 되돌린다.**
  리듬 교정에는 **수정률 상한(50%)과 의미 보존 6점 자가검증**이 따라붙는데 이 스킬에는 그 가드가 없다.
  등급이 C·D면 "`humanize-post` 재실행 권장"을 다음 단계 안내에 명시한다.
- **저자 색은 지적하지 않는다.** `AI_KOREAN_PATTERNS.md` Part B 9항목은 검토 대상이 아니다.
- frontmatter 영역과 스캐폴드 잔재는 본문 검토와 섞지 않는다.
- 글이 길면 모든 문장을 인용하지 말고 중요한 지적부터. 같은 패턴 반복은 첫 사례만 인용하고 "유사 사례 N건"으로 묶는다.
