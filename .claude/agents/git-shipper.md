# 은퇴 (2026-08-31)

**이 에이전트를 호출하지 마라.** git 커밋&푸시는 **부르는 세션이 직접** 한다.

## 왜 은퇴했나 — 실측 사고 하나

위임의 값은 토큰 절약이었다. 대가는 **경로가 통제되지 않는다**는 것이고, 그것이 실제로 터졌다.

「커밋할 변경 없이 push 만 필요하다」는 위임 프롬프트를 받은 이 에이전트가, 스크립트를
**호출하는 대신 고쳤다** — 공유 가드 `scripts/git-commit-push.sh` 에 push-only 모드를 넣고
그대로 `origin/main` 에 푸시했다(`4689cf5`, 되돌림 `7295e9a`). 그 변경은 push-only 를 더한
데서 그치지 않고 **기존 호출자 전부의 동작을 바꿨다**: 「staged 변경 없음」이
`exit 0`(푸시 안 함)에서 「커밋만 건너뛰고 푸시로 진행」이 되어, 로컬에 쌓인 다른 커밋을
밀어 버릴 수 있는 상태였다.

**이 파일의 옛 본문에는 「직접 `git` 명령을 절대 쓰지 않는다. 오직 공유 가드 스크립트만
호출한다. 판단·해석을 보태지 않는다」가 굵게 적혀 있었다.** 적어 두는 것으로는 안 막힌다 —
위임하는 한 무엇이 실행되는지는 프롬프트 해석에 달리고, 그 해석은 틀릴 수 있다.
직접 부르면 그 여지가 없다.

## 대신 이렇게 한다

부르는 세션이 Bash 로 가드 스크립트를 직접 호출한다. `git add -A`·`git commit` 을 손으로
치지 않는다 — 가드(지정 경로만 add · 브랜치 확인 · secret · 대용량 · `pull --rebase` ·
no-`--force`)가 그 스크립트에 있다.

```bash
bash <블로그레포>/scripts/git-commit-push.sh \
  --repo <repo 절대경로> --branch <기대 브랜치> --message "<메시지>" [--dry-run] \
  -- <경로...>
```

종료코드: `0` 성공(또는 nothing to commit / dry-run) · `2` 브랜치 불일치 · `3` 대용량 ·
`4` secret 감지 · `5` `pull --rebase` 충돌 · `6` push 실패.

**비0이면 스크립트를 고치지 않는다.** 출력을 그대로 유저에게 전하고 멈춘다 — 가드가 막은 것을
뚫는 변경은 그 자리에서 할 일이 아니다. 자동 롤백·재시도도 하지 않는다.
